# 일봉 수집의 검증과 단계별 공개

2026-09-24 감사 수정. 실제 운영 원본/정제 DB는 이 작업으로 변경하지 않았다. 다음 설명은 **다음 수집 실행부터** 적용되는 수집기 코드다. 과거 DB 전체가 자동으로 정정됐다는 뜻이 아니다.

## 응답 검증

필수 일봉 배열이 없거나 배열 타입이 아니면 오류다. 응답/각 행에 종목·거래소 식별자가 있으면 요청값과 일치해야 한다. 식별자 자체가 없는 공식 응답은 요청 identity를 사용한다. 날짜가 없는 행이나 비객체 행을 조용히 버리지 않는다. 날짜 형식, 숫자의 유한성, OHLC 범위, 정수·비음수 거래량, 중복 날짜의 내용, 최신→과거 정렬, 연속조회 키를 검사한다. 키가 있는 빈 연속조회, 반복 키, 충돌하는 중복 봉은 거부한다. 키움의 방향 부호가 붙은 가격은 기존 규칙대로 절대값으로 정규화한다. 정제 전 원본의 유효한 0원/0거래량 봉을 이 단계에서 임의 삭제하지 않는다.

명시적으로 존재하는 빈 최종 배열은 최초 무이력 종목일 수 있다. 그러나 빈 응답으로 기존 공개 이력을 지우지는 않는다. 응답에 식별자가 없으면 공급자의 잘못된 종목 반환을 독립적으로 증명할 수 없다는 한계는 남는다.

## 수정주가 기준을 섞지 않는 공개 단위

기존의 ‘새 페이지에서 이전 마지막 날짜를 만나면 중단’ 방식을 없앴다. 수정주가는 분할/과거 정정 때 오래된 가격까지 바뀔 수 있기 때문이다. 최초 조회와 완료 종목 갱신 모두 종목별 전체 이력을 **별도 세대**에 받는다.

1. 기존 `daily_bars`는 그대로 두고 새 `daily_generations`를 시작한다.
2. 페이지는 `daily_generation_bars`에 저장한다. 중단/실패해도 이 부분 자료와 기존 공개 데이터가 남는다.
3. 재시작 시 첫 페이지를 다시 대조한다. 달라졌으면 부분 세대를 보관한 채 새 전체 조회로 시작한다. 국내 조회 기준일도 세대에 고정한다.
4. 끝까지 조회한 뒤 첫 페이지를 다시 확인하고, 한 SQLite 트랜잭션으로 해당 종목 이력과 완료 상태를 교체한다.
5. 교체 전 정확한 행은 `daily_generation_previous`에 보관한다. 실패한 갱신이 기존 공개 완료 상태를 오류로 덮지 않는다.

수집 세대마다 lease와 소유 토큰을 사용한다. 같은 종목을 두 수집기가 동시에 쓰면 거부하며, 만료 후 다른 수집기가 이어받으면 이전 소유자는 저장/공개할 수 없다. 공개 직전 원래 `daily_bars` fingerprint도 대조하므로 별도 도구가 중간에 원본을 수정한 경우 덮어쓰지 않는다.

브로커가 point-in-time snapshot ID를 제공하는 것은 아니다. 전체 조회·페이지 겹침 검사·처음/마지막 anchor 대조는 관측된 수정주가 변화를 잡지만, 첫 페이지에는 나타나지 않는 공급자의 임의 과거 정정까지 수학적으로 배제하지 못한다. 장중 당일 봉이 계속 바뀌면 공개를 보류할 수 있으므로 안정된 장 마감 이후 수집이 적합하다.

## 비용·재개·관측

`--refresh-complete`는 이제 최근 구간만 받는 빠른 업데이트가 아니라 전체 세대 갱신이다. 요청 횟수·소요 시간·저장 공간이 늘어난다. `--max-pages-per-symbol`은 새로 저장하는 페이지 수를 제한한다. 재시작/공개용 첫 페이지 확인 요청은 추가로 발생한다. 과거 수집기의 미완료 포인터는 새 수정주가 기준을 증명하지 못하므로 안전하게 전체 조회로 전환한다.

공개 완료 수와 별도 미완료 세대 수를 분리해 출력한다. DB에서 점검하려면 다음 읽기 전용 조회를 사용한다.

```sql
SELECT symbol, exchange, status, pages, updated_at, error
FROM daily_generations
WHERE active = 1;
```

이전/중단 세대를 자동 삭제하지 않는다. 장기간 반복 갱신하면 저장 공간이 크게 늘 수 있다. 보존기간·압축·정리 정책은 별도 백업 및 승인 후에 결정해야 한다. 실물 DB에 새 수집을 시작하거나 기존 clean-v1을 재생성하는 작업은 이번 코드 검증과 구분한다.

검증은 임시 SQLite와 가짜 응답만 사용했다. 분할·역분할/가격 정정, 페이지 상한 뒤 재개, 네트워크 오류·키보드 중단, 중간 원본 변경, 반복 연속조회, 잘못된 종목/거래소/필드, 동시 소유권을 회귀 검사한다. 실제 계좌/API 요청은 하지 않았다.
