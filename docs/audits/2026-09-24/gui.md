# GUI·버튼·표시 문구 적대적 검토

기준: 2026-09-24, `codex/optimization-adversarial-audit`, HEAD `6e3ace7`. 변경하지 않은 제품 코드 검토이며, 이 문서와 검증 산출물만 작성했다.

## 요약과 범위

- 일반 V00 데스크를 임시 DB·가짜 서비스로 생성하고 모든 주요 탭을 순회했다. 계좌/API 조회, 실제/모의 주문, 감시 시작은 수행하지 않았다.
- 입력·버튼·체크박스·탭·레이블 256개를 런타임 목록화했다. QPushButton 28개, QLabel 131개, Qt 내부 구현 위젯 56개가 포함된다. 전체 목록은 [gui-controls.md](controls.md), 선택지·도움말·초기 표시/활성·소속 탭·판정은 [gui-inventory.json](../../../outputs/optimization-audit/gui-inventory.json).
- 모델·네트워크·실거래 성능이 아니라 UI 처리 경로와 표시 일관성을 검토했다. 모든 입력 조합이나 모든 가능한 동적 문자열까지 검증했다고 주장하지 않는다.
- 별도 GUI 중심 회귀 실행은 232개 실제 테스트가 통과했다. 잘못 적은 모듈명 `test_signal_connection_gui` 때문에 명령 전체는 loader error 1로 종료했으며 제품 결함으로 세지 않는다. 실제 모듈 `test_signal_status`와 상태/장부/브랜딩 테스트 36개를 추가 실행해 모두 통과했다. 따라서 실제 실행된 268개 테스트는 통과했지만 최초 명령 자체가 성공한 것은 아니다.

## 발견 사항

### GUI-01 · P1 · 실전 환경인데 연결 상태 문구는 모의주문이라고 표시

- **분류:** 재현된 표시 결함. 주문 안전장치 우회가 확인된 것은 아니다.
- **위치:** `dockdack/signal_connection_gui.py:94-95`; 모드는 `dockdack/watch_gui.py:654-660`에서 이미 전달된다.
- **재현:** `connection_view({'orders_enabled': True, 'trading_mode': 'real'})['gate']`가 `ON … 모의주문`을 반환한다.
- **영향:** 사용자가 실전 자동주문 허용 상태를 모의 환경으로 오인할 여지가 있다. 상단 실전 배지와 경고는 별도로 존재하지만 같은 창의 설명이 모순된다.
- **개선:** 선택 환경에서 공통 표시 모델을 만들고 연결 페이지도 `실전·실제 자금`/`모의·가상 자금`을 같은 상태로 렌더링. 모드 누락 시 모의라고 가정하지 않고 미확인 표시.
- **판정:** 문구 삭제보다 수정. 환경·주문 위험 안내는 유지. **작업량:** 소, 작은 작업. **수용 기준:** DEMO/REAL/미확인 × ON/OFF/예약 조합 테스트.

### GUI-02 · P2 · 두 모델은 정상 수신해도 연결 확인/파일 검사는 기본 파일만 본다

- **분류:** 재현된 상태·진단 연결 누락.
- **위치:** `dockdack/watch_gui.py:720-741`, `771-791`, `951-960`; 추가 모델 연결 `dockdack/v00_app.py:431-441`; 상단만 별도 보완 `v00_app.py:383-390`.
- **재현:** 두 prototype의 개별 JSON에 유효한 빈 신호 목록을 써 수신시키면 두 reader는 `ok`. 기본 `external-model` 파일은 만들지 않아 `missing`. 그런데 `외부 신호 연결` 주탭은 source_id가 `external-model`, 입력도 기본 `exchange/signals.json`, 안내도 `입력 파일 없음`이다. 상단에는 `외부 AI 2개 …`가 보인다. 주문/모델 추론 없이 재현했다.
- **영향:** 사용자가 정상 동작하는 모델을 끊긴 것으로 오인하거나, 잘못된 파일을 검사한다. 현재의 source_status 요약이 있어도 상세 진단과 연결 설정이 한 소스 기준으로 분리되어 있다.
- **개선:** 소스별 행/카드와 선택 소스의 입력·접수·생존·검사 결과를 통합. `파일 검사`는 선택 출처 또는 모든 출처 대상으로 명시. 사용하지 않는 기본 placeholder reader는 별도 비활성 카드로 표시하거나 설정 시에만 생성하는 설계 검토.
- **판정:** 두 모델 독립성은 유지, 구식 단일 소스 상태 UI는 교체/통합. **작업량:** 중, 중간 작업. **수용 기준:** 기본 파일 없음+모델 둘 정상, 하나 오류+하나 정상, 세 번째 임의 공급원 조합에서 상태/검사 대상 일치.

### GUI-03 · P2 · ‘일지 새로고침’은 UI 스레드에서 전체 장부를 읽고 손익을 재계산

- **분류:** 재현된 UI 응답성 결함. 실제 대규모 계좌 장부의 지연 시간은 측정하지 않았다.
- **위치:** `dockdack/trade_journal_gui.py:62`, `191-203`. 일반 자동 갱신은 이미 `dockdack/watch_gui.py:1122-1171`의 worker 경로를 사용한다.
- **재현:** 임시 저장소의 order_history에 인위적인 200ms 지연을 넣어 버튼 클릭. 읽기 스레드 ID와 GUI 스레드 ID가 일치했고 클릭이 약 201ms 동안 반환하지 않았다. 미리 예약한 Qt heartbeat도 클릭 중 처리되지 않았다. 수치는 실제 DB 속도 예측이 아니라 동기 경로의 재현 증거다.
- **영향:** 장부 증가나 DB 잠금 시 OFF/중지 등 다른 UI 응답도 늦어진다. SQLite 연결의 timeout=5초(`watchlist.py:329`)는 이 위험을 더 키울 수 있다.
- **개선:** Portfolio/OrderHistory처럼 `request_refresh` 신호를 내고 기존 직렬 LedgerCollector worker를 재사용. 갱신 중 중복 클릭 합치기, 완료/오류 상태 표시.
- **판정:** 버튼 유지, 동기 구현 제거. **작업량:** 소-중, 작은~중간 작업. **수용 기준:** 인위적 느린 DB/큰 장부에서도 50ms heartbeat 유지, 주문 상태 전환 UI가 막히지 않음.

### GUI-04 · P2 · 모델 보유분 현재가 하나를 받으면 다른 보유 행까지 재생성

- **분류:** 재현된 불필요 렌더링. 실제 장중 FPS/CPU 손실은 추가 계측 필요.
- **위치:** `dockdack/portfolio_gui.py:327-341`, `386-430`.
- **재현:** 같은 종목의 두 lot 행+무관한 다른 종목 한 행인 임시 포트폴리오에서 첫 종목 시세 하나를 갱신. QTableWidget.setItem이 36번 호출되어 3행×12열 전체가 재생성됐다. lot 없는 일반 경로는 변경 셀만 갱신한다.
- **영향:** 모델 lot/보유 종목 수가 늘면 종목별 시세마다 전체 시장 정렬·확장·셀 생성이 반복된다. 현재가 갱신은 로컬 UI 부담인데 거래 DB/모델 추론 최적화와 혼동하면 병목을 놓치기 쉽다.
- **개선:** `(시장, 거래소, 종목, lot_id)` 키에서 행을 찾는 인덱스 유지. 수량/원가/lot 집합 변경 때만 구조 재생성하고 시세/목표 셀만 갱신. 최소 변경부터 시작해 필요하면 QAbstractTableModel으로 이행.
- **판정:** 모델별 행은 반드시 유지. 전체 rebuild 경로만 교체. **작업량:** 중, 중간 작업. **수용 기준:** 무관한 행의 셀 객체/선택/스크롤 유지, 한 시세 갱신 작업량이 해당 lot 수에만 비례.

### GUI-05 · P2 · 최소 높이가 780이라 768px 화면에 창 자체가 맞지 않음

- **분류:** 재현된 레이아웃 제약. 실제 Windows 125/150% DPI 화면 검증은 미수행.
- **위치:** `dockdack/watch_gui.py:190-191`.
- **재현:** offscreen Qt에서 1366×768 요청 시 실제 창은 1366×780. 기본 보유종목 페이지/한국어 폰트를 사용한 시험이며 창 장식·작업표시줄 높이는 이보다 추가로 필요하다. 매매 설정은 세로 스크롤이 약 400px 이상 존재한다(현재 문자열·배치에 따라 변동).
- **영향:** 일반 노트북의 사용 가능 화면 영역에서 하단 상태문구가 밖으로 나갈 수 있고 고배율에서는 더 악화된다. F11은 우회 수단이지 기본 크기 적합성 해결이 아니다.
- **개선:** availableGeometry 기반 초기 크기, 더 낮은 최소 높이, 상단 상태/조작 영역 재배치와 본문 스크롤. 긴 기술 설명은 상세 도움말로 접되 핵심 위험/현재 상태는 숨기지 않기.
- **판정:** 버튼 삭제로 억지 축소하지 말고 배치 최적화. **작업량:** 중, 중간 작업. **수용 기준:** 1366×768/1280×720, DPI 100/125/150%, 긴 오류문구에서도 OFF/중지와 현재 환경이 항상 접근 가능.

### GUI-06 · P2 · 시작/설정 변경의 동기 DB 읽기·쓰기 잔존

- **분류:** 코드로 확인된 성능 위험. 사용자 실DB의 시작 시간/락 지연은 미측정.
- **위치:** `dockdack/watch_gui.py:202-209`, `1083-1114`; `dockdack/watchlist.py:1086-1091`; `dockdack/v00_app.py:309-311`.
- **근거:** 창 생성 중 활성 종목마다 cached_snapshot이 별도 SQLite 연결/쿼리를 연다. 모델 체크 변경은 GUI 콜백에서 UPDATE 및 전체 테이블 reload를 수행한다. 로그/계좌 worker화가 됐어도 이 경로는 여전히 동기다.
- **영향:** 저장 이력/관심 종목 수나 DB 상태에 따라 시작·모델 전환이 느려질 수 있다. 200종목이면 snapshot만 최소 200번 연결/조회하는 구조다.
- **개선:** 단일 읽기 snapshot 배치 쿼리와 백그라운드 초기 로드, 마이그레이션/기간 업그레이드 작업의 worker화. 기존 캐시는 loading/이전값 표시 후 원자 적용.
- **판정:** 캐시/기간 보정 기능 유지. N+1·GUI-thread DB 접근 정리. **작업량:** 중, 중간 작업. **수용 기준:** 0/200/1000종목과 의도적 DB 락에서 responsiveness, 실패 시 이전 정상 화면 유지.

### GUI-07 · P3 · 새 모델별 원가 방식과 옛 ‘전체 FIFO’ 설명이 모순

- **분류:** 코드로 확인된 표시 불일치.
- **위치:** `dockdack/operations_gui.py:193`, `311`; `dockdack/trade_journal_gui.py:246`, `284`.
- **근거:** 공통 RETURN_DESCRIPTION(`dockdack/trade_journal.py:26`)에는 ‘모델 매도는 지정 매수분, 일반 매도는 FIFO’라고 되어 있지만 위 잔존 문구는 전체가 FIFO라고 설명한다.
- **영향:** 두 모델이 같은 종목을 서로 다른 가격에 매수한 경우 표시 손익의 계산 기준을 잘못 이해할 수 있다.
- **개선:** 계산 결과의 `basis`/lot 할당에 따라 설명을 공통 포매터에서 생성. 지정 매수 lot ID는 상세에서 표시. 세금·수수료 제외 경고 유지.
- **판정:** 잘못된 중복 문구 제거/교체 가능. **작업량:** 소, 작은 작업. **수용 기준:** 일반 FIFO, 지정 lot, 혼합 장부, 원가 미확인 각각 설명 일치.

### GUI-08 · P3 · 과거 전용 GUI는 숨겨져도 500ms마다 모델 표 전체 재생성

- **분류:** 정적 경로 확인. 현재 일반 V00 창에는 이 타이머가 없어 기본 데스크 성능 문제로 확대 해석하지 않는다.
- **위치:** `dockdack/mark1_gui.py:155-159`, `177-189`; `dockdack/mark1_prototype_gui.py:133-136`, `164-183`.
- **근거:** QTimer가 500ms마다 setRowCount/setItem 전체 루프와 resizeColumnsToContents를 호출하며, diagnostic revision 또는 현재 탭 표시 여부를 검사하지 않는다.
- **개선:** 구식 전용 화면을 계속 지원한다면 보이는 동안 변경 revision만 적용. 기존 일반 GUI 외 관찰 전용 도구는 연구/진단 패키지로 분리. 삭제는 실행 진입점·저장 장부·테스트와 의존성 전환 확인 후 결정.
- **판정:** 즉시 파일 삭제 금지. 관찰 전용 주문차단 역할은 독립된 의미가 있다. **작업량:** 작은 최적화는 소, GUI 계층 통합은 대.

### GUI-09 · P3 · 상단/설정에서 연결 탐색이 중복되고 고급 설정이 일반 설정과 섞임

- **분류:** UX 판단, 제품 고장으로 확정한 항목 아님.
- **위치:** `dockdack/watch_gui.py:625-638`, `845-909`; `dockdack/v00_app.py:204-239`; 런타임 목록 참조.
- **관측:** 주탭 ‘외부 신호 연결’과 매매 설정 안의 ‘외부 신호 연결’ 이름이 같지만 다른 내용을 보여준다. 두 prototype 체크와 모델 경고 아래에 기존 내장 LSTM, 기본 source_id/경로, 추가 JSON source, 랜덤 모의 신호기가 겹친다. `파일 검사`는 형식검사이고 `신호 파일 1회 읽기`는 실제 후보 접수라 같은 무주문 도구처럼 보여도 의미가 다르다.
- **개선:** ‘연결’ 한 페이지 안에 소스별 상태·설정·검사를 배치하고 ‘고급 연결/레거시/테스트’는 접기. one-shot ingest는 ‘신호 수신 시험·주문후보 등록’처럼 효과를 명시. 모델 위험 안내는 짧은 핵심+항상 접근 가능한 상세로 구성.
- **판정:** 중복 탐색과 반복 설명은 통합 가능. 기능 차이가 있는 검사/접수, ON/OFF/감시중지는 합쳐서 의미를 잃으면 안 된다. **작업량:** 중, 중간~큰 작업.

### GUI-10 · P3 · 접근성과 표준 입력 동작 보완 후보

- **분류:** 정적/런타임 UX 검토. 실제 스크린리더/키보드 전수 사용 검증은 미수행.
- **위치:** `dockdack/watch_gui.py:500-518`, `566-595`, `859-906`; `dockdack/v00_widgets.py:62-65`.
- **근거:** 여러 수량·금액·기간 입력은 시각적 QLabel에 의존하며 명시적 accessibleName/buddy가 없다. SourceList는 16개를 넘겨 ‘추가’해도 아무 안내 없이 return한다.
- **개선:** 명시적 입력 이름/단위/도움말, label buddy, 일관된 Tab 순서; source 최대치에서는 버튼 비활성+16개 제한 안내. 임의 keyboard shortcut은 주문 실행에 직접 연결하지 말 것.
- **판정:** 텍스트를 모두 지우기보다 중복은 줄이고 입력 의미/위험 단위는 보강. **작업량:** 소-중, 작은~중간 작업. **수용 기준:** 키보드 단독 탐색, 접근성 이름 검사, 16/17번째 추가 경계 테스트.

### GUI-11 · P3 · 모델 추정 확률과 검증된 성공률의 표현을 구분

- **분류:** UX/문구 정밀성 판단. 화면의 연구 검증 미통과 경고 자체는 이미 존재한다.
- **위치:** `dockdack/v00_app.py:120-130`의 prototype 설명, `dockdack/mark1_prototype_gui.py:119`의 보정 성공확률 열 제목.
- **영향:** ‘성공확률 50% 초과’라는 짧은 문구만 보면 실제 장중 매매 성공률이 검증되었다는 뜻으로 읽힐 수 있다. 일봉에서 보수적으로 정의한 사건의 모델 추정값과 실제 체결 이후 성공률은 같지 않다.
- **개선:** ‘모델 추정 확률 >50% (연구용·장중 성과 미검증)’처럼 표시하고, 상세에서 사건 정의/비용/연구 실패 경고를 유지. 한 모델은 미국 과거 시가 매수 신호 0건이고 다른 모델은 비용 반영 손실이라는 기존 내용도 삭제하지 않는다.
- **판정:** 오해 소지가 있는 제목은 수정, 위험 경고는 보존. **작업량:** 소, 작은 작업. 동적 과거 성과 수치는 모델 manifest에서 가져와 이름만 바뀌고 경고가 남는 문제도 방지.

## 확인되어 보존할 설계

- quote progress는 DB를 다시 읽거나 관계없는 차트를 그리지 않도록 캐시/서명 비교가 있다.
- 숨겨진 로그는 주기적으로 DB를 다시 읽지 않으며, LedgerCollector revision으로 변하지 않은 전체 계산을 건너뛴다.
- Portfolio의 계좌 원합계와 모델별 virtual lot 표시를 분리하고, 공유 매도가능수량을 단순 합산 가능 수량으로 표시하지 않는다.
- 주문 OFF/감시 OFF는 별개로 표현하며 이미 접수된 주문을 취소한다고 오도하지 않는다.
- 창 닫기/Esc/전체화면은 native controls와 worker 종료 상태를 구분하는 회귀 테스트가 있다.
- mark1 prototype 관찰 전용 GUI의 주문차단은 일반 GUI와 의도적으로 다르므로 ‘중복 화면’이라는 이유만으로 코드를 지우면 안 된다.
