# DockDack 적대적 검증 — 발견 사항

2026-09-28 · 작업·게시 브랜치 `mark_1` · `main` 병합은 사용자 요청으로 보류

이 문서는 모델의 예측 정확도·수익률·추론 속도를 평가하지 않는다. 버튼과 상태 표시, 감시·주문 경계, 화면 가시성, 저장소·배포 계약을 검토했다. 실제 증권사 주문, 운영 장부 변경, GPU 학습은 수행하지 않았다. 아래의 ‘확정’은 소스 추적 또는 가짜 서비스/임시 DB/오프스크린 Qt에서 재현한 뜻이지 실계좌에서 발생했다는 뜻이 아니다. 해결 내용과 최종 검증은 [해결 및 검증](remediation.md)에 분리한다.

## 방법과 범위

- 감사 시작 시점의 추적 파일 610개와 무시 규칙·임시 산출물·비밀 설정·봉인 모델 경로를 목록화하고, 주요 UI/주문/감시 진입점을 정적으로 추적했다. 기존 [2026-09-24 파일·컨트롤 인벤토리](../2026-09-24/README.md)는 당시 시점의 기록이며 현재 UI 전수 검증으로 간주하지 않았다.
- 오프스크린 Qt에서 가짜 서비스와 임시 SQLite로 800×520 및 1280×720 창을 실행했다. 상단 자동주문, AI 선택·비중, 보유종목, 일지, 주문·체결, 고급설정, 관심종목·차트의 배치와 작업 중 편집 가능 여부를 확인했다.
- 정기·수동 TOP100 경로의 의존성을 추적하고, 계좌 API가 실패하는 가짜 객체로 순위 적용 여부를 재현했다. 실제 Kiwoom API는 부르지 않았다.
- Git 원시 바이트와 Windows 작업본 개행, 모델 봉인 SHA-256을 비교했다. 해시가 일치하는 현재 작업본만 확인하는 것으로 다른 OS의 clean checkout이 안전하다고 추정하지 않았다.

## 확정 발견

아래는 **수정 전 재현 상태**다. 현재 해결 여부는 [해결 및 검증](remediation.md)에 기록했다.

## 삭제·구조 판단과 미검증 영역

추적 파일에서 `__pycache__`, 로그, SQLite DB, IDE 설정, 가상환경, 임시·빌드 산출물의 잘못된 커밋은 발견하지 못했다. Mark1.1의 원본/명명 번들에 있는 동일한 모델 바이트는 각각의 봉인·호환 계약에 필요하며 오래된 호환 진입점과 연구 파일도 이름이나 유사 코드만으로 ‘쓸모없다’고 삭제하지 않았다. 추적 Markdown 상대 링크 744개 중 대상이 없는 3개는 모두 2026-09-24의 **역사적 파일 인벤토리**가 당시 경로를 가리키는 경우다. 현재 사용 안내의 누락 링크는 발견하지 못했다. 관련 회귀와 사용자 데이터 보존 계약을 깨지 않는다는 증거가 없으면 삭제는 개선이 아니다.

이 감사가 모든 함수·버튼 조합을 증명하지는 않는다. 실제 키움 응답·장중 지연·체결, 125/150% DPI와 스크린리더, 외부 AI 프로세스의 모든 실패 조합, 모델 성능은 별도 검증이 필요하다. 이전 감사의 장기 과제 및 보존 사유는 [2026-09-24 보고서](../2026-09-24/README.md)와 [당시 개선 기록](../2026-09-24/remediation.md)을 참조한다.
