# mark_1 후속 심층 모델: 논문 근거와 실험 원칙

조사일: 2026-09-16. 이 문서는 **실험 전 연구 제안**이다. 아래 추천 구조의 수익성이나 성공률 향상을 확인했다는 뜻이 아니며, 실제 구현·학습 설정·측정 결과는 해당 실행의 manifest와 결과 보고서가 기준이다. 논문을 그대로 재현한 구현과 논문에서 아이디어만 가져온 구현을 구별한다.

## 유지할 사용자 계약

- 과거 완료된 30개 일봉의 OHLCV와 당일 가상 매수가만 입력한다. 31번째 값은 완성된 당일 봉이 아니라 **매수가 질의**다.
- 정답은 `high >= entry * 1.01 AND low > entry * 0.991`이다. 양쪽 경계에 모두 닿으면 손절 우선 실패로 처리한다.
- 보정된 성공확률 `p > 0.5`에서만 매수 신호를 낸다. 정확히 0.5는 대기한다.
- 익절 +1%, 손절 −0.9%는 바꾸지 않는다. 실제 보유 평균단가 기준이다.
- 일봉의 같은 날 고가·저가를 사용한 정답은 장중 진입 **이후**의 경로를 관측한 정답이 아니다. 모형을 깊게 만들어도 이 정보 부족은 해결되지 않는다.
- 자동주문을 켜거나 원본·정제 DB를 변경하는 연구가 아니다.

## 추천 구조: 깊이·다중 시간 규모·대조군

### 1. Query-conditioned 1D ResNet — 우선 후보

과거 30일의 특징을 1D 잔차 블록으로 인코딩하고, 전체 평균·최근 시점 표현에 가상 매수가/마지막 종가 비율을 결합한다. 같은 과거 30일에 서로 다른 가격을 질의하는 문제라는 의미를 보존한다. 31개 토큰 인터페이스를 유지하더라도 내부에서 과거와 query를 분리할 수 있다.

후보 범위는 3~12개 잔차 블록, 블록당 2~3개의 짧은 1D 합성곱, 너비 64~128, dropout 0.1~0.2다. 가장 먼저 고정한 **얕은/깊은 한 쌍**으로 깊이 효과를 확인한다. 입력 30개를 초기에 과도하게 축소하지 않으며, 수백 층을 무조건 쌓지 않는다. 잔차 연결은 최적화를 돕는 구조이지 새로운 가격 정보를 추가하는 장치가 아니다. 이 설계는 원 논문의 정확한 구조·학습 설정과 다른 paper-inspired 실험이다.

### 2. Short-window InceptionTime — 다른 가설의 후보

짧은/중간/긴 패턴을 병렬로 읽는 모듈 6개를 기본 비교 대상으로 한다. 30개 관측에 맞춰 커널 3/7/15, bottleneck과 모듈당 4개 경로를 제안한다. 3모듈 단위 잔차 연결과 같은 query 결합법을 사용한다. 원 논문의 10/20/40과 다른 커널이므로 단순 재현이라고 부르지 않는다.

고정된 서로 다른 seed 3개 이상을 각각 보고하고, 앙상블 규칙을 성과 확인 전에 고정한다. 한 번 잘 나온 seed만 고르지 않는다. 앙상블도 독립된 보정 기간에서 다시 보정한다. 충분한 계산 자원이 있다면 같은 구조 5-seed 평균을 추가할 수 있지만, 성공을 보장하지는 않는다.

### 3. Feature MLP / 기존 TCN — 반드시 남길 비교 기준

기존 MLP를 동일한 새 데이터 기간·학습 예산에서 다시 학습한다. 과거만으로 계산하는 수익률·변동성·봉 모양·거래량 비율을 사용하는 작은 MLP도 유용한 비교 기준이다. 기존 TCN까지 포함하면 “깊이 증가”, “입력 표현 개선”, “더 많은 학습”의 효과를 구별할 수 있다. 깊은 모델이 이 기준을 못 이기면 큰 모델이라는 이유만으로 승격하지 않는다.

## 특징과 목표함수

이 절은 논문의 직접적인 결론이 아니라 현재 입력·정답 계약에서 도출한 설계 제안이다.

1. 가격 단위 대신 로그 수익률/마지막 과거 종가 대비 비율을 사용한다. 완료된 30봉으로만 몸통, 윗꼬리·아랫꼬리, 고저 폭, true range, 과거 거래량의 상대 변화를 계산한다.
2. 과거 5/10/20일 추세·실현 변동성·평균 범위는 새 외부 정보가 아니라 현재 30봉을 읽기 쉬운 형태로 요약한 것이다. 학습 없는 고정식 또는 학습 기간에서만 적합한 스케일러를 사용한다.
3. 당일 최종 고가·저가·종가·거래량은 **정답 계산에만** 사용한다. 미래 값으로 entry 후보를 고르거나 입력을 정규화하지 않는다.
4. 성공확률이 목적이므로 우선 unweighted binary cross entropy를 유지한다. 성공 표본 가중치를 키우거나 oversampling해 매수확률만 올리는 방식은 실제 사전확률과 출력 해석을 바꾼다. 시도하려면 별도 실험으로 기록하고 독립 기간에서 다시 보정한다.
5. 가격 증강/무증강 대조군은 남긴다. 동일한 30일에서 만든 5개 가격은 독립 관측 5개가 아니다. base-event별 총 가중치를 맞추고, 같은 이벤트의 변형을 서로 다른 분할에 넣지 않는다.
6. 고가/저가 거리 같은 보조 목표를 추가한다면 성공 BCE를 대체하지 않는다. 동일 모델의 auxiliary-loss 유무를 분리 비교해야 효과를 설명할 수 있다.

### 가상 가격 증강에서 꼭 밝혀야 할 점

정답은 두 부등식 `entry <= high / 1.01`, `entry < low / 0.991`의 교집합이다. 다른 값이 같으면 가상 entry를 낮출수록 성공하기 쉬워진다. **실제 당일 저가보다 낮아 거래된 적 없는 가상 가격도 성공 정답을 받을 수 있다.** 이는 데이터 수를 늘리는 동시에 실제 주문 문제와 어긋나는 반사실 표본을 만든다.

따라서 실제 시가 진입을 기본 평가로 유지하고, 가상 가격 실험은 별도 표기한다. 일봉만으로 임의 장중 매수가의 실제 체결과 체결 후 경로를 검증할 수 없다는 한계는 모델 종류와 무관하다.

## 검증 프로토콜: 오래 학습하는 것과 오래 성과를 맞추는 것을 구분

- 사전에 후보 구조·seed·epoch 상한·early-stop 규칙·평가지표를 고정하고 실행 설정을 저장한다. 손실이 줄어드는 동안 더 학습할 수 있지만, 평가 기간 결과를 보고 학습을 계속하는 것은 별개의 모델 선택이다.
- 종목별 랜덤 분할 대신 공통 날짜로 나눈다. 과거 30봉 입력 구간이 다음 분할에 겹치지 않도록 purge한다. pooled-symbol 표본 수와 독립 날짜 수를 모두 보고한다.
- 가능한 여러 과거 시점의 walk-forward에서 학습 → 별도 tune → 별도 calibration → 다음 기간 평가 순서를 반복한다. 변형 선택에 사용한 모든 기간은 development 기간이다.
- **이미 보고 사용자가 확인한 2025년 이후 백테스트는 더 이상 처음 보는 최종 시험이 아니다.** 다시 평가해 개선 폭을 비교할 수는 있지만 `reused historical evaluation`로 명시해야 한다. 날짜를 새 이름으로 다시 나누는 것만으로 완전히 미사용된 시험이 되지는 않는다.
- 새 결과를 보고 다시 수정할수록 모든 시도를 같은 연구 이력에 추가한다. 재사용 구간의 상승만으로 실전 일반화를 입증하지 않는다. 실제 미사용 미래 구간을 모은 뒤 고정 모델을 평가해야 신뢰도를 더 높일 수 있다.
- Brier/log loss, PR-AUC, `p > 0.5`의 신호 수·날짜 수·적중률, 확률 구간별 실제 성공률, 비용 후 기대값·낙폭을 함께 본다. 1건의 성공률과 수천 건의 성공률은 같은 증거가 아니다.
- 일자별로 여러 종목이 함께 움직이므로 기본 불확실성은 날짜 cluster bootstrap으로 보고한다. 연속 날짜 의존까지 고려하려면 고정한 여러 날짜의 moving-block bootstrap도 민감도 분석으로 둔다. 한 방식의 구간을 독립 표본 신뢰구간처럼 과장하지 않는다.
- 같은 신호에 대해 익절/손절 미도달 시 당일 종가 청산과 다음 날 보유를 구별한다. 단일 세션 정답으로 학습한 모델을 무기한 보유 전략에서 평가하면 목표 기간이 달라진다. 미관측 가격·거래정지·단일가 봉을 이상적인 체결로 덮지 않는다.

## 50% 성공률과 수익률은 다른 목표

모든 거래가 정확히 +1% 또는 −0.9%로 끝나고 왕복 비용을 0.2%로 단순화하면 기대값은 `0.01*p - 0.009*(1-p) - 0.002`다. 0이 되는 확률은 약 **57.9%**다. 이는 이 과제의 숫자에서 계산한 이상화된 예시이며, 실제 비용 예측이나 권장 매매 기준이 아니다. 갭·미도달·정지·체결 오차가 있으면 이 식 그대로 적용할 수 없다.

사용자가 정한 `p > 0.5`는 그대로 두되, “50%를 넘었으니 수익이 난다”고 보고하지 않는다. 성공확률과 비용 후 기대 수익은 별도로 측정한다. 기준 미달이면 더 깊은 후보도 **연구용**으로 남기고 자동주문용 우수 모델로 승격하지 않는다.
