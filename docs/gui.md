# DockDack 0.2 트레이딩 GUI

현재 기본 창은 **0.2 통합 GUI**이며 `DockDack.vbs`로 실행한다. 전체 기능과 사용 조건은 [현재 기능서](FEATURES.md)를 먼저 참고한다. 기존 장중 모델은 [MK1·MK1.1 안내](MARK1_1_PROTOTYPE.md)와 [Mark1.2 재검토](../reports/mark1-2-20260925-review/REPORT.md), 일봉 대리모델은 [Mark1.13–1.22](mark1-intraday-proxy.md)와 [Mark1.23–1.28](mark1-target-horizon-methods.md), 장전 모델은 [Mark1.3 모델](mark1-3-model.md)과 [연구 로드맵](mark1-5-research-roadmap.md)에 정리했다. prototype 사용에는 `uv sync --extra gui --extra prototype`이 필요하다. 모델 선택·프로그램 실행만으로 주문하지 않는다. 아래 개별 시세/수동 주문 화면은 고급·호환 기능으로 구분한다.

> **현재 기능의 기준은 [0.2 기능서](FEATURES.md)**다. [ver 0.0 안내](VER_0_0.md)는 2026-09-16의 과거 기능·검증 이력으로 보존한다.
> 일반 화면의 모델 설정은 **AI 추론 모델**, 공통 주문·연결과 수동 규칙·구형 모델은 상단 **고급설정** 탭에서 확인한다. 고급설정 탭을 선택해도 주문 설정은 바뀌지 않는다.

Windows에서 검증한 PySide6 화면이다. **기본은 모의투자**이며 상단 모의/실전 버튼으로 환경을 선택한다.
`.env`의 `DOCKDACK_TRADING_MODE=real`만으로 GUI가 실전으로 시작하지 않는다.
실전은 경고 확인, 실전 키, 주문 허용 설정이 모두 필요하며 실제 계좌 주문 검증은 수행하지 않았다.
[거래 환경 선택](trading-modes.md)과 [매매일지](trade-journal.md)를 참고한다.

## 실행

첫 설치:

```powershell
uv sync --extra gui --extra prototype
```

이후 프로젝트 폴더의 `DockDack.vbs`를 더블클릭한다. 터미널 창 없이 GUI를 연다.
VBScript가 비활성화된 환경에서는 다음 명령으로 실행한다.

```powershell
uv run --extra gui --extra prototype dockdack-gui
```

`.env` 위치와 모의 키 설정은 [브로커 문서](kiwoom-broker.md)를 참고한다.
파일은 프로젝트 루트에서 읽으며 키나 토큰을 화면에 표시하지 않는다.

## 이전 수동 트레이딩 화면 사용 (고급·호환)

1. 왼쪽 삼성전자·SK하이닉스·애플·알파벳 A를 누르거나, 위 입력란에 코드/티커를 입력해 조회한다.
2. 미국 거래소는 자동 조회한다. 조회가 어려우면 검색 옆에서 NASDAQ/NYSE/AMEX를 선택한다.
3. 현재가와 전일대비가 표시된다. `15초 자동 조회`는 선택한 종목의 시세만 갱신한다.
4. 오른쪽 주문 유형·수량을 선택하고 매수 또는 매도를 누른다.
5. 최종 확인창의 종목·수량·단가·금액을 확인하고 전송한다. 돌아가기를 누르면 주문하지 않는다.
6. 계좌·주문 내역 조회 버튼으로 잔고, 선택 종목의 미체결 및 당일 주문·체결 내역을 확인한다.

주문 유형:

- **현재가 조회 → 지정가**: 주문 버튼을 누를 때 최신 현재가를 다시 조회한다. 미국 가격은 API 단위($1 이상 소수 2자리, 미만 4자리)에 맞춰 매수 내림·매도 올림하며 수량은 유지한다. 전송 전 최종 지정가를 확인한다.
  확인창에서 본 가격을 그대로 사용하며, 확인 뒤 가격을 자동 변경하지 않는다.
- **지정가 직접 입력**: 입력한 가격으로 주문한다. 국내는 정수 원, 미국은 달러 기준이다.
- **시장가 (국내)**: 단가를 정하지 않고 주문한다. 미국 모의투자는 지원하지 않아 전송 전에 안내한다.

현재가 지정가도 체결을 보장하지 않는다. 주문 접수 후 실제 체결 상태는 당일 주문·체결 탭에서 확인한다.
성공 코드나 주문번호가 빠진 응답은 **접수 여부 확인 필요**로 표시한다. 미접수로 단정하거나
자동 재주문하지 않으며, 수동으로 주문·체결 내역을 조회한 뒤 다음 행동을 결정해야 한다.
주문 접수 후 계좌/주문 내역을 한 번 갱신하며, 이후 상태는 조회 버튼으로 확인한다.
장 종료·주문 거절·응답 오류에 자동 재주문하지 않는다.
기존 주문 취소/정정 버튼은 이번 GUI에 포함하지 않았다.

API 요청 중에는 종목 변경과 주문 버튼이 잠기지만 창은 계속 반응한다.
종목 조회가 실패하면 기존 종목으로 잘못 주문하지 않도록 주문 버튼을 비활성화한다.
조회 오류는 하단과 활동 로그에 표시한다. 활동 로그는 현재 실행 중인 세션의 최근 200건이며
파일로 저장하지 않는다. 조회 내역은 API의 최대 10페이지 범위이며, 뒤에 더 있는 경우 일부만 성공으로 보여 주지 않고 오류를 표시한다.
요청 중 창 닫기는 응답이 돌아올 때까지 보류한다. 창을 닫아도 접수된 주문이 취소되지는 않는다.

## 테스트

```powershell
uv run --extra gui python -m unittest discover -s tests -v
```

테스트는 가짜 응답과 화면 밖 Qt 창을 사용하며 계좌에 주문을 보내지 않는다.
GUI 선택 의존성이 없으면 Qt 테스트는 건너뛰고 나머지 테스트는 실행한다.

## 관심종목 · 자동매매 창

### 운영 대시보드 · 보유종목과 주문 기록

주탭 순서는 **관심종목 → 보유종목 → 매매일지 → 주문·체결 → AI 추론 모델 → 고급설정**이다. AI 화면의 하위탭은 **모델 선택 → 모델 성과**이며, `공통 주문·연결`은 고급설정에 둔다. 고급설정은 오른쪽 아래 버튼으로 숨기지 않고 상단 탭에서 언제든 선택한다. 상단에는 **자동주문 상태 → 최근 조회 요약 → 선택한 AI 모델 수**를 같은 높이의 카드로 모은다. 최근 요약에는 의미 있는 판단 3개와 나머지 개수를 표시하고 전체 모델별 판단은 툴팁에 둔다. 숫자는 프로세스 연결 성공 수가 아니며 확인된 신호 오류는 점검 배지와 툴팁으로 표시한다. 자동주문을 끄면 반복 감시도 중단한다. **고급설정**에는 전체 1회 조회·감시 시작/중지·종합 TOP100 재선정·차트 내보내기·조회 간격·종목 관리·공통 주문·연결·추가 JSON 신호기·서버 로그가 있다. 앱이 열리면 한국·미국 잔고를 기존 비동기 경로로 자동 조회한다. 보유종목 탭을 클릭하거나 이미 선택된 탭을 다시 누르면 잔고 재조회를 요청하며, 시장별 최소 60초 간격과 진행 중 작업 예약은 그대로 적용된다. API 응답 전에는 조회 중/기존값을 구분하며 자동주문은 OFF다. 관심종목 목록과 실제 계좌 잔고를 혼동하지 않도록 별도 화면으로 나눈다.

모의 보유의 자동매도 조건이 맞으면 과거 거래일의 접수 확인된 매수 기록만으로 매도를 보류하지 않는다.
현재 미체결 없음·정확한 보유/매도가능수량을 재확인하고, 그 근거가 실제 전송 직전까지 15초 이내인 경우 별도 매도를 진행한다.
당일/접수 불명 매수·이미 진행 중인 매도·모델별 장부 대조 실패는 계속 보류하며 이유를 로그에 표시한다.
과거 매수 기록과 출처 미확인 표시는 보존한다. 현재 모의 계좌 전체 마감 청산 기능은 제거됐다. 모델별 기간 매도는 확인된 그 모델의 매수분에만 적용하고, 수동·출처 미확인·다른 모델 보유분은 일괄 청산하지 않는다.

- **보유종목**: 한국·KRW / 미국·USD 탭을 나눠 각 시장의 잔고 요약과 보유 종목만 표시한다.
  한국·미국 계좌를 각각 조회해 보유 수량, 매도 가능 수량, 평균 매수가, 현재가,
  평가금액, 평가손익, 수익률과 모델별 예정 매도 시점을 보여준다. 체결 관측일 등 기한을 확정할 근거가 없으면 `확인 필요`로 남긴다. 미국 탭의 원화 토글은 유효한 최근 참고환율로 금액을 환산해 볼 뿐, 원본 USD·주문·장부를 변경하지 않는다. OFF/ON 왕복은 마지막 유효 환율을 즉시 재사용하고 `환율 갱신`만 새 조회를 요청한다. 금액 앞 `≈` 표기와 중복 USD 줄은 숨긴다. 넓은 화면에서는 표의 열이 남는 폭을 사용한다. 예수금과 주문가능금액은 계산·표시에서 구분하고 KRW/USD는 합산하지 않는다. 카드 아래의 잔고 기준·종목 수·D+1/D+2 추정 안내 줄은 표시하지 않으며, 오류 상세는 상태 툴팁에서 확인한다.
- **주문·체결**: 이 앱의 자동주문 장부를 표시한다. HOLD나 매매 신호는 이 표에 들어가지 않는다.
  접수·미확정·체결·거절·취소·미전송을 구분하고 체결 확인/접수 대기 등으로 필터링할 수 있다.
  부분체결과 잔량 취소도 구분한다. 체결가는 증권사에서 확인한 값만 표시한다.
  **체결가 다시 확인**으로 이전 기록의 가격을 보완할 수 있으며 확인되지 않은 가격은 `미확인`으로 남긴다.
  매도별 대응 원가·실현손익·실현 수익률을 따로 표시하며 주문 직전 현재가로 체결가를 대신 채우지 않는다.
  수동 주문 및 다른 앱에서 보낸 주문은 이 로컬 자동주문 장부에 포함되지 않는다.
- **고급설정 → 서버·감시 로그**: 서버·오류 / 시세·차트 감시 / 매매 신호를 각각 별도 로그로 조회한다.
  HOLD는 매매하지 않음, BUY/SELL은 주문 전 후보 신호다. 자동주문 OFF에서도 감시/신호 기록은 늘어날 수 있다.
  주문 처리 단계별 로그는 주문·체결 화면의 별도 탭에서 확인한다.
- **관심종목**: 한국·KRW / 미국·USD 탭에 시장별 종목 수와 목록을 표시한다. 저장된 완전한 순위가 있을 때 관심종목과 일반 감시는 시장별 정확히 100종목으로 제한하며, 순위 밖 보유·미확정 주문 이력은 별도로 보존한다.
  작은 창에서도 차트의 최소 크기를 확보하고 관심종목 표의 많은 모델 열은 표 내부에서 가로로 스크롤한다. 넓은 창에서는 차트 폭을 제한해 표가 우선 공간을 차지한다.
  시장별 선택 종목과 스크롤 위치를 유지하고, 종목 추가 시 해당 시장 탭에서 새 종목을 선택한다.
  빈 시장에서는 다른 시장 차트나 규칙 입력을 남기지 않는다.
  관심종목 표에는 **선택된 모델의 판단 열만** 표시하고 현재가 바로 옆에 조회 시각을 둔다. 모델을 OFF로 바꾸면 그 열만 숨기고 내부 기록은 지우지 않는다. 열 순서는 장중 조회 모델·장전 모델·현재가·조회이며 마지막 두 열은 항상 맨 오른쪽이다. 현재가 셀은 통화 약자를 붙이지 않은 숫자 한 줄이며 통화는 시장 탭·필요 시 툴팁에서 확인한다. 미판단 상태는 `—`로 표시한다. Mark1.0–1.2만 장벽 추정확률, Mark1.13–1.22와 Mark1.23–1.28은 서로 다른 일봉 대리점수, 장전 모델은 고유 점수와 매수 후보 여부를 나타낸다. 과거 판단은 현재 후보와 구별하고 서로 다른 점수를 평균내지 않는다. 선택 종목의 차트 위에는 현재가와 직전 완료 종가 대비 변동률만 간결하게 표시한다.
- **AI 추론 모델 → 모델 선택**: 장중 확률 Mark1.0–1.2, 장전 점수 Mark1.3–1.12, 장중 일봉 대리 Mark1.13–1.22, 장중 목표가·보유기간 연구 Mark1.23–1.28을 얇은 섹션 헤더로 구분한다. 카드별로 모델 이름·학습·출력·매도 설명을 별도 칸에 표시한다. 각 모델 카드의 `1회 매수`에서 해당 모델 주문의 평가자산 비중 상한을 정한다. 숨긴 과거 체크박스의 OFF 값으로 고정수량 모드로 돌아가지 않는다. 감시·작업·주문 준비 중에는 비중을 바꿀 수 없다. 장전 결과 표에는 후보 점수와 이전 장 여부만 보여주고 빈 시장 상태 박스는 표시하지 않는다. 기타 신호 기본 비중·JSON 경로·주문 상한은 **고급설정 → 공통 주문·연결**에서 정한다. 저장된 선택이 없는 새 모의 계정은 29개 모두 초기 선택하되 감시·자동주문은 OFF로 시작한다. 기존 계정의 저장 선택은 유지하고 실전 계정은 제공 prototype을 초기 선택하지 않는다.
- **AI 추론 모델 → 모델 성과**: 등록된 모델의 국내·미국 행을 두고 현재 계정의 저장 체결 장부를 원매수 모델별로 집계한다. 매도 체결이 없으면 0%가 아니라 `매도 체결 없음`이다. 출처 미확인·수동 거래는 보고서에 보존하되 모델 성과표에는 가상의 모델 행으로 추가하지 않는다. KRW/USD를 나누고 원가·체결가 미확인분을 구분하며, 수수료·세금 제외 실현손익이지 백테스트나 계좌 전체 수익률이 아니다. 상세 조건은 [현재 기능서](FEATURES.md)를 따른다.
- **매매일지**: 국내·미국별 주문 날짜를 일·월·연 단위로 전환한다. 미국 탭의 원화 환산은 처음 켰을 때 ECB의 최근 일별 고시를 조회해 참고값으로 표시하고, OFF/ON 왕복은 마지막 유효 환율을 즉시 재사용한다. 새 조회는 `환율 갱신`에서 요청한다. 첫 조회에 유효한 고시가 없으면 USD를 유지하고, 갱신 오류·잘못된 응답은 이전 유효 환율과 고시일을 보존한다. 원본 USD·주문·실제 체결 손익은 바꾸지 않는다.

관심종목과 보유종목의 시장 탭은 화면 표시만 나눈다. 탭을 전환해도 양쪽 시장의 감시·잔고 갱신·정시
재선정·차트 내보내기는 유지되며, 현재 자동주문 허용 상태를 변경하지 않는다.

상단에는 자동주문 상태, 최근 조회, 선택 모델 수를 순서대로 표시한다. 최근 조회 카드에는 중요한 판단 최대 3개와 나머지 개수를 보이고 전체 모델 내용은 툴팁에 둔다. 활성 **Mark1.0–1.2 장벽 모델** 모두가 **같은 종목·시세**를 유효하게 판단하면 해당 종목·가격·조회 시각·확률 단순평균을 한 번에 갱신한다. 장중 Mark1.13–1.28 일봉 대리점수와 장전 점수는 평균에 넣지 않으며 새 대리점수 도착을 기다리느라 기존 평균을 보류하지 않는다. 새 조회의 일부 결과만 도착한 동안에는 직전 완료값을 그대로 보여주고 추론 진행률은 상단에 표시하지 않는다. 첫 완료 전에는 확률 `—`이며 모델 구성이 바뀌면 이전 평균을 재사용하지 않는다. MK1.0·MK1.2는 +1%/−0.9%, MK1.1은 +0.5%/−0.4%를 예측하므로 서로 다른 목표의 평균은 거래 신호가 아니다. 고급설정의 서버 화면에서 마지막 작업
응답과 종료 시각도 확인한다. 작업 중 120초 이상 진행 응답이 없으면 지연 확인 안내를 표시한다.
앱 응답 시각이 갱신되는 것만으로 API 연결 정상이나 주문 체결을 보장하지 않는다.

감시 중 잔고는 기존 API 작업 스레드에서 시장별 최소 60초 간격으로 순차 조회한다.
보유종목 탭 클릭·재클릭과 새로고침 버튼의 재조회도 이 제한을 따르며, 다른 요청이 진행 중이면 조회를 예약한다. 클릭 없이 같은 탭에서 화면만 보고 있을 때 반복 호출하지 않는다.
감시가 꺼져 있을 때도 탭 선택이나 새로고침 버튼으로 잔고만 조회할 수 있고 자동주문 허용 상태를 바꾸지 않는다. 정상 완료를 알리는 긴 하단 문구는 표시하지 않으며 오류·잔고 기준 시각은 보유종목 상태에서 확인한다.
가격/손익은 각 시장 카드에 표시된 잔고 조회 시각 기준이다. 120초가 지나면 오래된 값으로 표시한다.
조회 실패 시 이전 정상 잔고를 보존하고 오류를 표시하며, 미조회/실패를 보유종목 0개로 표시하지 않는다.
처음 정상 조회한 빈 계좌만 `보유종목 없음`으로 표시한다.

분류별 최근 500건의 로그와 최근 500건의 주문을 화면에 표시하며 전체 기존 기록은 로컬 DB에 보존한다.
신호가 많이 들어와도 다른 분류의 기록이 밀려 보이지 않도록 분류 후 표시 개수를 제한한다.
화면 전환·잔고 조회·로그 열람은 주문 ON/OFF 상태를 변경하지 않는다.

### 체결가 보완과 실현손익

**주문·체결 → 체결가 다시 확인**은 조회만 수행한다. 다른 API 작업 중이면 조회를 예약하며,
주문 ON/OFF, 기존 주문의 상태, 미체결·미확정 주문 차단을 변경하지 않는다. 감시 중에도 자동으로 보완을 시도한다.

- 검사 간격은 최소 60초, 같은 시장·조회일 재시도는 자동 300초 / 수동 60초 이상이다.
  한 번에 최대 4개 시장·조회일 묶음만 조회하며 API 공통 호출 간격도 따른다. 버튼을 반복 눌러 제한을 우회하지 않는다.
- 화면의 최근 500건뿐 아니라 전체 저장 장부에서 가격이 빠진 접수·체결·부분체결 후 취소 기록을 찾는다.
  관심종목에서 제외한 종목의 과거 주문도 포함하지만 접수 여부가 불명확한 주문을 자동 해제하지 않는다.
- 주문번호의 앞자리 0을 정규화한 뒤 시장·조회일·종목·방향·원주문 수량·거래소를 대조한다.
  복수 후보나 상충 내역은 보완하지 않는다. **미국 과거 내역은 조회일의 시간대 근거 미확인으로 자동 가격 보완을 보류**한다.
  주문번호가 같거나 후보가 하나뿐이어도 조회일을 독립적으로 확인한 것으로 취급하지 않는다.
- 일자별 조회의 체결단가가 여러 주의 가중 평균이라는 보장은 없다. **주문 1주·체결 1주가 확인된 값** 또는 원주문·누적 체결수량·체결금액 등을 대조해 평균가 근거를 확인한 값만 사용한다.
  다수 체결의 미확인 평균가, 누락·0 가격, 조회 실패를 현재가·주문가 또는 0원으로 대신하지 않는다.
  행의 설명에서 조회 결과, 가격 출처, 미확인 이유를 확인할 수 있다.

모델별로 배분한 매도는 **지정된 원매수 건의 원가**를 사용해 다른 모델의 매수분을 차감하지 않는다. 일반 매도는 같은 시장·거래소·종목의 앞선 매수 수량부터 대응하는 **주문순서 FIFO**를 유지한다.
전체 로컬 장부를 사용하지만 일반 거래의 FIFO는 실제 체결 순서가 아니라 저장된 주문 순서 기준이며, 모델 구분도 앱의 가상 보유분이므로 세무·증권사 공식 손익과 다를 수 있다.
실현손익은 확인된 매도대금에서 대응 매수 원가를 뺀 값이며 실현 수익률은 그 원가 대비 비율이다.
수수료·세금은 제외하고 KRW/USD를 합산하지 않는다. 매수 기록·체결가·대응 수량이 부족하면 손익을 `미확인`으로 표시한다.
확인된 매도만 합산한 경우에는 미확인 건수를 함께 표시한다. 이는 **이 앱의 자동주문 장부 손익**이지 계좌 전체 손익이나 잔고의 평가손익이 아니다.

증권사가 제공하는 과거 조회 범위를 넘는 내역은 복구되지 않을 수 있다. 미국의 일반 당일 주문 체결 확인은 기존 경로를 유지하며,
위의 과거 보완 기능이 미국 기록을 복구했다고 주장하지 않는다. 근거 없이 인접 날짜의 주문을 끌어와 채우지도 않는다.

### 최소화 · 최대화 · 전체화면

트레이딩 데스크와 관심종목 창 모두 제목 표시줄의 기본 최소화/최대화 버튼을 사용한다.
화면 안의 중복 최소화·최대화 버튼은 제거하고 전체화면 버튼만 제공한다.

- **최소화 (제목 표시줄)**: 작업 표시줄로 창을 내린다. 감시와 자동매매는 중지되지 않는다.
- **최대화 / 이전 크기 (제목 표시줄)**: 작업 표시줄을 유지한 최대 크기와 일반 창 크기를 전환한다.
- **전체화면 / 창모드**, **F11**: 제목 표시줄 없이 화면을 채우고, 다시 누르면 이전 일반 창 크기로 복원한다. 최대화에서 진입했어도 해제 시에는 크기를 조절할 수 있는 일반 창으로 돌아온다.
- **Esc**: 전체화면 또는 최대화를 해제하고 일반 창 크기로 복원한다. 이미 일반 창이면 창을 닫거나 자동매매를 중지하지 않는다.

자동매매 중단은 **감시·주문 중지** 버튼을 사용한다. 창 닫기(X)의 기존 안전 중지 동작은 유지한다.
프로그램 코드 변경은 재실행 후 적용되며, 화면 모드 전환 자체는 주문 설정을 변경하지 않는다.

### 관심종목과 신호 설정

상단 상태 카드는 **현재 주문 허용 상태**를 표시하고, 고급설정에서 조회 전용 감시를 별도로 제어한다.

- **자동주문 ON · 주문 허용**: 정규장에 신호·잔고 등 주문 조건을 충족하면 새 주문을 전송한다.
- **자동주문 OFF · 주문 차단**: 반복 감시도 중단한다. 이미 전송 중이거나 접수된 주문을 취소하는 기능은 아니다. 조회 전용 감시는 고급설정에서 별도로 시작할 수 있다.
- **전체 조회 완료 후 ON 예정**: 현재는 OFF이며, 한 번 확인한 자동 활성화가 대기 중이다. 같은 상단 상태 버튼을 다시 눌러 예약을 취소할 수 있다.

별도의 켜기·끄기 버튼은 없다. 상단 **자동주문 OFF/ON** 상태 버튼 하나를 누를 때마다 전환한다.
OFF 상태에서는 조회 중에도 누를 수 있다. 확인창을 한 번 승인하면 진행 중인 전체 조회 완료를 기다려 ON으로 전환한다.
감시가 꺼져 있거나 쉬는 중이면 전체 조회부터 시작한다. 잔고 조회나 목록 편집 같은 별도 작업이 진행 중이면
그 작업을 마친 뒤 전체 시세·차트 조회를 한 번 진행한다. 별도로 감시 시작을 누르거나 조회 후 다시 켜기를 누를 필요가 없다.
예약 중에도 주문은 OFF이며 중복 클릭으로 예약을 추가하지 않는다.

현재 전체 관심종목이 **이번 순회에서** 모두 정상 조회되고, 해당 시장 잔고가 정상/최신이며,
사용 중인 외부 신호/정시 선정에 오류가 없어야 ON으로 전환한다. 이번 예약 도중 외부 신호 오류가 발생하면
나중에 복구되더라도 해당 예약은 취소한다. 실패 시 주문은 OFF이고 자동으로 다시 켜지지 않는다.
같은 상태 버튼으로 OFF로 돌리거나 고급설정의 감시·주문 중지를 누르면 대기 예약도 취소하고 반복 감시를 중단한다. 늦은 조회 완료나 오래된 시작 콜백으로 다시 켜지지 않는다.
오류로 주문이 해제되면 진행률 갱신과 독립적으로 배지와 버튼을 갱신한다.

현재 통합 데스크에서 관심종목 추가/제외, N일 일봉 차트, 매매 설정과 모의 자동주문을 관리한다. 관심종목과 활동 기록, 계정별 v4 화면 설정은 로컬 SQLite에 저장된다. 조회 간격·모델 선택·신호 경로/상한·모델별 1회 매수 비중·기타 신호 기본 비중·탭·창 크기는 재실행 후 복원된다. 과거 v1–v3 공통 매수 비중은 모델별 초기값으로 승계하며, 제거된 전체 계좌 마감 청산 선택은 복원하지 않는다. 종목별 일봉 수는 관심종목 행에 저장된다. 명령줄에서 모델을 지정했다면 그 실행에서는 저장된 모델 선택보다 우선한다. 감시/자동주문은 항상 꺼져 있으며 실전 계정과 인증정보는 복원하지 않는다.
이전 수동 GUI의 **관심종목 · 자동매매** 버튼은 별도 창을 열며 그동안 기존 거래 화면의 요청을 잠근다. 이는 현재 prototype을 별도 관리 창에 연결한다는 뜻이 아니다.
자세한 규칙과 안전 제한은 [자동매매 사용법](autotrading.md)을 참고한다.
현재 통합 데스크에서는 한국·미국 각각 종합 TOP100 선정, 차트 JSON 내보내기, 외부 매매 신호 연결을 제공한다. 재선정·내보내기 버튼은 **고급설정 → 조회·감시**에 있다. 구버전 거래대금 조회 도우미와는 별개다.
**AI 추론 모델 → 모델 선택**에서 학습 방식·출력·매도 시점과 선택 상태, 모델마다 0.01–100%의 `1회 매수` 비중을 확인·변경한다. 옆의 **모델 성과**에서는 저장 체결 실적을 확인한다. **고급설정 → 공통 주문·연결**에는 기타 외부/구형 신호의 기본 비중과 JSON 경로·수량·금액 상한을 둔다. 모델별 비중은 주문 예산 상한이며 Mark1.8 동결 투자비중이 더 낮으면 그 값을 적용한다. 중복된 `신호 연결 확인` 바로가기와 독립된 `상태·검사` 화면은 제거했다. 내장 테스트, 구형 모델, 사용자 추가 신호기 및 서버 로그도 고급설정에서 확인한다.
**기존 장중 장벽 모델** Mark1.0·1.1·1.2는 각각 독립된 모의 전용 외부 프로세스·신호 출처를 사용한다. Mark1.0/1.1은 CatBoost 3-seed, Mark1.2는 국내 CNN·미국 LSTM 3-seed로 학습했다. 각 모델이 완료 30봉+현재가로 추정한 성공확률이 50%를 넘으면 모의 매수 후보를 낼 수 있다. 확인된 각 모델 매수분은 Mark1.0/1.2가 +1% 익절·−0.9% 손절, Mark1.1은 +0.5% 익절·−0.4% 손절 기준을 사용한다.
**장중 조회용 일봉 대리모델** Mark1.13–1.22도 각각 독립된 모의 신호 출처와 국내/미국 학습 가중치를 사용한다. 추세 지속·과매도 반전·돌파·변동성 국면·거래량 압력·초단기 반전·캔들 위치·추세 가속·변동성×거래량·압축/확장의 10개 특징 가설이다. 완료 30봉과 조회 시점 현재가로 점수를 계산하고 0.5 초과를 매수 후보로 보며, 확인된 자기 매수분에만 +1%/−0.9% 가격 기준을 적용한다. 그러나 학습 정답은 다음 세션의 **관측 시가와 당일 전체 고저가**로 만든 대리사건이다. 장중 진입 이후 고저가 도달 순서나 수익성은 검증하지 않았다. 장중 장벽 3개 모델의 확률 평균에도 섞지 않는다. 입력·학습 범위와 봉인 결과는 [별도 문서](mark1-intraday-proxy.md)에 있다.
**목표가·보유기간 일봉 대리모델** Mark1.23–1.28도 독립된 모의 전용 신호 출처다. 완료 30봉 중 모델별 10/20/30봉과 조회 현재가로 다음 날 **관측 시가 기준** 목표 도달 대리점수를 계산한다. 확인된 자기 매수분에만 모델별 +2–4% 목표가를 먼저 적용하고, 미도달 시 체결이 확인된 세션을 1일째로 세어 10/20번째 거래 세션 마감 5분 전부터 기간 매도를 시도한다. 손절은 없으며 주문·체결은 보장되지 않는다. 장중 진입 이후 실제 고가 발생 시점·첫 도달·지정가 체결·수익성은 검증하지 않았다. [방법과 제한](mark1-target-horizon-methods.md)을 참고한다.
**장전 모델**에는 Mark1.3–1.12가 있다. 모두 완료한 30일봉으로 개장 10분 전 해당 시장 후보를 한 번에 판단하고 상위 후보를 동결한다. Mark1.3은 30봉에서 추출한 8개 특징의 CUDA 학습 MLP 순수익 회귀다. Mark1.4 국내 모델은 추세·변동성·거래량/유동성 압축 특징을 학습한 신경망, 미국 모델은 같은 날 100종목의 다음 날 상대 순수익 순위를 학습한 신경망이다. Mark1.5는 LSTM 순수익 회귀, Mark1.6은 30×5 CNN, Mark1.7은 같은 날짜 종목 attention 순위, Mark1.8은 비용·하방위험 점수와 투자비중 직접 학습, Mark1.9는 평균−불확실성망, Mark1.10은 최악 연도·40bp 견고성 유전탐색, Mark1.11/1.12는 동결 유전망의 3/5거래 세션 보유형이다. 점수/%/0–1 출력은 서로 의미가 다르고 보정된 실거래 성공확률로 표시하지 않는다. Mark1.8의 종목별 학습 비중은 **그 모델 카드의 1회 매수 비중**보다 작으면 그 값을 적용하고 주문 상한도 넘지 않는다.
Mark1.4의 내부 장전 점수는 기존 거래량 상위 100종목으로 계산하지만, 실제 화면·실행기의 조회와 주문 대상은 **복합 TOP100**뿐이다. 거래량 순위에만 있는 후보는 복합 목록에 들어오지 않으면 신호·주문으로 이어지지 않는다.
장전 당일 종료형 모델은 **그 모델의 체결로 확인된 lot만** 마감 5분 전부터 가격과 관계없이 매도 신호를 낸다. 여러 거래일 보유형 모델은 정한 거래 세션 수가 지난 뒤 정규장 중 가격과 관계없이 매도 신호를 낸다. 이는 특정 시가·종가 가격 체결을 강제하는 주문이 아니다. 계좌 전체 보유분을 마감에 청산하지 않는다. 매수·매도 모두 감시·모의 자동주문 ON, 최신 시세, 미체결/잔고/매도가능수량 등 별도 검사를 거치며 체결은 보장하지 않는다.
Mark1.11/1.12는 실제 매수 **체결을 관측한 세션을 1일째**로 세어 3/5번째 거래 세션이 시작된 뒤 가격과 관계없이 매도 후보가 된다. 원 연구 백테스트는 다음 날 시가 진입, 보유기간마다 겹치지 않는 진입, 3/5번째 세션 종가 청산 가정이었다. 실제 모의 연결은 매일 후보를 낼 수 있고 장중에 매도하므로 그 백테스트 수익률이 운영 조건의 수익률을 보증하지 않는다.
저장된 선택이 없는 새 모의 계정은 Mark1.0–1.28 **29개 전체를 초기 선택**한다. 기존 계정의 유효한 저장 선택은 복원하고 사용자가 끈 모델을 임의로 다시 켜지 않는다. 실전 환경은 제공 prototype을 초기 선택하지 않는다. 선택을 해제해도 그 모델로 이미 확인된 매수분의 출처·매도 기한은 지우지 않는다. 연결/해제만으로 감시·자동주문을 켜지 않으며 실전 경로에는 prototype을 연결할 수 없다. GUI 짧은 설명은 방법과 출력 단위 중심이고, 과거 성과·연구 제한은 해당 연구 문서에서 확인한다. Mark1.3도 모의 신호에 연결됐지만 [재사용 역사 평가](mark1-3-model.md)는 수익성을 입증하지 못했다.
**관심종목**에는 ON인 모델별 매수·대기 판단만 별도 열로 표시한다. 기존 장중 세 모델의 마지막 유효 추정확률, Mark1.13–1.22의 당일 일봉 대리점수, Mark1.23–1.28의 목표·기간 대리점수, 장전 모델의 각기 다른 점수는 서로 구분하고 선택 종목 요약에는 현재가·조회 시각이 보인다. 이전 조회 판단은 현재 판단과 구분하고, 모델이 꺼져 있거나 처음부터 유효 판단이 없으면 값은 `—`다. 점수는 검증된 장중 적중률·수익률이나 주문 확정이 아니며 최신 시세/주문 적격성과 혼동하면 안 된다. 같은 종목의 체결 보유도 모델/원매수별로 분리해 각 목표가를 적용한다.
**파일 검사 (주문 없음)**는 감시 중에도 가능하며 신호 접수나 규칙 생성을 하지 않는다.
설정과 JSON 규격은 [외부 신호 연동](external-signals.md)을 참고한다.
**국내·미국 종합 TOP100 · 개장 10분 전 / 개장 / 매 정시**를 선택하고 감시를 시작하면 시장별 일정에 맞춰 목록을 갱신한다. 거래대금·거래량·상승률·하락률 상위에서 각 20개를, 미국에서는 시가총액 상위 20개도 모아 중복을 제거한다. 공식 예제에서 국내 시가총액 상위 전용 순위 API를 확인하지 못해 이번 구현에서는 그 범주를 적용하지 않는다. 각 시장의 남는 자리는 거래대금 상위 100개로 보충한다. 미국은 장전 09:20뿐 아니라 실제 개장 09:30에도 다시 선정한다. 적격 보통주 100개를 확정하지 못하면 불완전한 새 순위를 적용하지 않는다. 저장된 완전한 순위가 있으면 활성 관심/일반 감시 목록은 시장별 **정확히 100종목**으로 유지한다. 순위 밖 보유종목·미확정 주문은 이 100개에 더하지 않고 별도 경로에서 대조·매도를 계속한다. 장전 후보의 **실제 실행 대상**은 검증된 종합 순위 100종목이며, Mark1.4 내부 점수의 별도 거래량 100종목과 구분한다. 실시간 순위를 매 순간 추종하는 방식은 아니다.
과거 일봉은 DB에서 재사용하며 외부 모드에서는 종목별 JSON을 조회 직후 갱신한다.
**고급설정 → 모의 테스트 신호기**에서 미보유 종목 10% 매수 / 실제 평균 매입가 대비 +1% 익절 · -0.8% 손절 신호를 연결할 수 있다.
랜덤 신호 자체 수량은 1주지만 통합 데스크에서는 **고급설정 → 공통 주문·연결**의 기타 신호 기본 비중 예산으로 실제 매수량을 다시 계산한다. 초기값은 10%, 주문당 국내 1,000만원·미국 10,000달러 상한이며, 감시·자동주문은 OFF다. 초기 금액은 권장 투자금액이 아니므로 사용자가 확인해야 하며, 금액 0인 시장은 주문을 차단한다. 이전 수동 테스트기의 1주·금액 상한 0 기본값과 구분한다.
매도 직전 실제 평균 매입가와 현재가로 해당 익절/손절 조건을 재확인한다. 손절은 전량 청산이나 -0.8% 손실 상한 보장이 아니다.
상세 실행 순서는 [지속 감시 운영 안내](server-mode.md)를 참고한다.

### 화면 반응성과 호출 속도

시세 한 건이 들어오면 해당 행만 갱신하고, 변하지 않은 차트·보유종목·주문 셀을 다시 만들지 않는다.
숨긴 로그는 주기적으로 읽거나 그리지 않으며 탭을 열면 최신 상태를 반영한다.
분류 로그는 DB 인덱스와 최신 기록 번호를 사용하므로 HOLD가 많아져도 서버·주문 로그를 전부 스캔하지 않는다.
기존 전체 기록은 삭제하지 않는다.

상단 진행률은 **이번 전체 순회** 기준이며 ‘순회 후 대기’는 전체 순회 완료 후 쉬는 시간이다.
API 제한 대기는 GUI 작업 스레드에서 처리하고 응답 완료 시각으로 다음 요청 시간을 계산한다.
화면에는 안전 간격·남은 호출 대기·재시도 횟수를 표시한다.
공식 한도와 여유 간격, 재제한 시 동작은 [API 호출 속도 제어](api-rate-limits.md)를 참고한다.

### Windows 브랜드 표시

DOCKDACK 전용 컨택트 히터(똑딱이 타자) 마크와 이름을 사용한다. Windows 창·작업 표시줄에는
`dockdack/assets/dockdack.ico`, 벡터 원본에는 `dockdack/assets/dockdack-mark.svg`를 사용한다.
전용 Windows 앱 ID로 Python 기본 아이콘과 구분한다. 로고·아이콘과 창 모드 변경은 주문 설정을 바꾸지 않는다.
