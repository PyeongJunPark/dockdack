# mark1 prototype — 저장 모델 / 일반 GUI 모의 트리거

**현재 사용법(2026-09-24):** [외부 AI 두 모델 동시 연결 안내](MARK1_1_PROTOTYPE.md)를 따른다. mark1/mark1.1은 내장 드롭다운에서 제거하고 독립된 외부 체크박스로 연결했다. 같은 종목도 모델별 매수분으로 나누고 각 체결 원가·수량으로 청산한다. 아래 단일 내장 선택 방식은 최초 연결 당시의 개발 기록이다.

2026-09-16 최신 정밀도 우선 실험에서 **사전에 선정한 연구 후보**를 고정해 보존한 버전이다. 수익성 검증을 통과한 모델이나 실거래 배포 버전이 아니다. **별도 창이 아니라 일반 GUI에서 선택하는 모의투자 트리거**로 연결했다. 사용자가 직접 모의 자동주문을 확인한 경우만 동작하며 실전 주문은 차단한다. 이번 연결 작업에서는 실제 감시·자동주문을 시작하지 않았다.

사용자가 수정한 **main `b4b925c`의 ver 0.0 공통 GUI**를 `mark_1`에 반영했다. 같은 `V00Window`의 거래 설정에서 `없음 / LSTM30 mark0 / mark1 prototype`을 선택한다. 기존 보유종목·주문·로그·감시·확인창을 그대로 사용한다. main 작업 폴더의 코드를 직접 바꾸거나 Git 병합/커밋한 것은 아니다.

2026-09-24: 같은 선택기에 **[mark1.1 prototype](MARK1_1_PROTOTYPE.md)**(+0.5% / −0.4%)을 추가했다. 한 번에 한 모델을 선택하며 이 문서의 기존 mark1 모델·가중치·+1% / −0.9% 기준은 유지한다. 보유종목·실제 주문/체결·매매일지의 **매수 모델** 열에서 원래 매수 신호의 모델을 확인할 수 있다. 선택 모델을 변경해도 기존 보유분의 매수 출처와 매도 기준을 덮어쓰지 않는다.

## 실행

`mark_1` 작업 폴더의 **`DockDack.vbs`를 더블클릭**한다. 기존 통합 GUI이며 mark1을 선택하고 감시·자동주문 OFF로 열린다.

이 컴퓨터에서 사용한 명령:

```powershell
cd C:\Users\user\Desktop\dockdack-mark_1
& C:\Users\user\Desktop\dockdack\.venv-ml-cuda\Scripts\python.exe -m examples.run_desktop_gui --trigger mark1-prototype
```

- `거래 설정 → 내장 매수 트리거 → mark1 prototype`을 선택한다. 별도 mark1 관리 탭은 추가하지 않는다.
- 모의 환경, 관심종목·수량/매수 비중·시장별 금액 상한을 확인한 뒤 **기존 모의 자동주문 ON 확인 버튼으로 사용자가 직접 시작**한다. 트리거 선택·프로그램 실행만으로 감시하거나 주문하지 않는다.
- 감시만 켠 상태와 자동주문 ON은 다르다. 감시 중 성공확률이 높아도 자동주문 OFF이면 주문하지 않는다. 조회 전에는 확률을 만들어 표시하지 않는다.
- 최신 main과 같이 해당 시장의 정규장 중 관심종목을 조회한다. 장이 닫혀 있어 새 확률이 없는 상태와 모델이 실제로 판단한 대기는 구분해서 본다. API 키 오류·봉 부족 역시 별도 조회 오류다.
- 매수 신호는 미보유 상태에서 보정 성공확률 **50% 초과**일 때이며, 정확히 50%는 대기다. 주문 전과 최종 전송 직전에 새 현재가 및 실제 지정가에서 다시 추론한다. 모의 매수로 등록된 mark1 보유분은 실제 평균 매입가 대비 **+1% / −0.9%**를 별도 보유종목 매도 순회에서 검사한다. 일봉 부족이나 순위 제외만으로 매도 감시가 끊기지 않는다.
- 기존 수량·금액 제한 및 비중 매수 설정을 유지한다. 종목별 상한, 예수금/주문가능금액, 미체결·중복 매수 차단도 그대로 적용한다. 정상 GUI의 거래량 TOP100 설정을 사용하며 시작 시 관심종목을 임의로 2종목으로 바꾸지 않는다.
- mark1 이전 보유분과 다른 전략의 보유분은 기존 저장 목표가 또는 기본 +1%/−0.8%를 유지한다. mark1 선택만으로 전체 계좌의 기존 손절 기준을 바꾸지 않는다. 같은 종목을 수동 청산 후 다시 수동 매수한 경우 과거 전략 표지가 남을 수 있으므로 목표가를 확인해야 한다(종목 단위 기록이며 개별 매수 건 분리 아님).
- API 설정은 이 작업 폴더의 `.env`, 없으면 기존 형제 `dockdack/.env`를 **현재 프로세스에서만** 읽는다. 복사하거나 출력하지 않는다. 명시적으로 `--env-file`을 지정할 수도 있다. 키가 없으면 창/모델 확인은 가능하지만 실제 조회는 실패한다.

기존 자동매매를 재시작하거나 키·모델을 교체하지 않는다. 실행기는 현재 작업 폴더의 일반 장부를 우선하며, 없으면 형제 `dockdack/.dockdack/lstm30-demo/watchlist.sqlite3`를 **복사 없이 재사용**한다. `--store`로 명시할 수도 있다. 같은 장부는 실행 잠금으로 두 창의 동시 사용을 거부한다. mark1 선택 시 완료 30봉 확보를 위해 기존 조회 길이가 31 미만이면 31로 올린다. 기존 장부는 통합 GUI의 필요한 테이블만 추가하는 비파괴 마이그레이션을 적용한다.

별도 관찰창 바로가기 `Mark1Prototype.vbs`는 혼동을 줄이기 위해 제거했다. 연구 진단 소스와 기존 `.dockdack/mark1-prototype/` 기록은 보존하며 필요할 때 `python -m examples.run_mark1_prototype_gui`로 관찰 도구를 열 수 있다. 평소에는 `DockDack.vbs` 일반 GUI를 사용한다.

## 보존한 모델

저장 위치: **`models/mark1_prototype/`**, 버전 **`20260916-v1`**.

| 시장 | 저장한 후보 | 구성 | 현재 판정 |
| --- | --- | --- | --- |
| 국내 | CatBoost `cat_joint6` | seed 42·43·44의 3개 모델 + 보정식 | 연구 기준 미통과 |
| 미국 | CatBoost `cat_binary8` | seed 42·43·44의 3개 모델 + 보정식 | 연구 기준 미통과, 과거 평가 매수 0건 |

이는 최신 실험에서 선정한 트리 앙상블이다. 이전 ResNet·MLP 등 신경망 가중치를 새 이름으로 붙인 것이 아니다. 시장별 최종 `walk_2024` 모델의 native `.cbm` 3개씩, 보정식, 고정 정책, 184개 입력 특성의 순서, 파일/추론 코드 SHA-256, 출처·성능·위험 경고를 함께 저장한다. 추론 시 전체 학습 캐시나 원본 학습 결과 폴더는 필요 없다.

번들과 해시 검증에 쓰는 세 추론 의존 소스는 `.gitattributes`에서 자동 줄바꿈 변환을 끈다. 이후 Git에 저장하거나 다른 컴퓨터에서 꺼낼 때 줄바꿈만 바뀌어 무결성 검사에 실패하지 않도록 바이트를 보존한다. 실제 코드를 변경하면 새 버전으로 재검증해야 한다.

이전 `models/mark1/*.pt`, 정제 DB, 원 실험의 모든 모델은 그대로 남긴다. 이 저장 작업은 재학습이나 데이터 오류 수정이 아니다. 자세한 성능은 [원 연구 보고서](../reports/mark1-selective-20260916/REPORT.md), 가격 단위 문제는 [미국 데이터 진단](mark1-us-signal-diagnosis.md)에 있다.

## 입력과 의미

완료된 과거 30거래일 OHLCV와 후보 현재가로 184개 특성을 만든다. 당일 최종 고가·저가·종가·거래량은 모델 입력으로 사용하지 않는다. 학습 대상은 다음 보수적 하루 전체 사건이다.

- 당일 고가가 후보 매수가의 1.01배 이상
- 당일 저가가 후보 매수가의 0.991배 **초과**
- 두 경계에 모두 닿으면 손절 먼저로 처리해 실패

현재가는 입력할 수 있지만 **임의 장중 매수 이후 남은 시간의 익절/손절 순서가 검증된 확률은 아니다**. 학습·역사 평가는 실제 시가 기준이었다. 같은 날 이미 매수가 이전에 발생한 저가를 일봉만으로 구별하지 못한다.

국내는 이전 심층 후보보다 재사용 역사 결과가 개선됐으나 비용 후 여전히 손실이고, 미국 0신호는 성공이 아니다. FCEL·BNED·BBSI의 주식분할/병합 가격 단위 문제가 확인된 정제 버전을 사용한 모델이므로 데이터 경고도 유지한다. 국내 전체 데이터가 무결하다는 인증 역시 하지 않는다.

## 모의 실행 경계

일반 GUI용 출처는 `source_id=mark1-prototype-demo-trigger`, 환경은 `demo`다. 신호 식별자에도 예약된 mark1 출처 표지를 붙이며, 수신·설정·주문 직전·최종 전송에서 실전 사용을 거부한다. 모델 검증 연결이 없거나 현재가 확률이 50% 이하로 바뀌면 모의 주문도 차단한다. 새 확률은 매수가 후보 가격이 바뀔 때마다 계산하며 오래된 가격의 예측을 재사용하지 않는다. `BUY`는 매수 후보이지 접수·체결이 아니다.

저장 번들의 `research_only=true`, `research_qualified=false`, `deployment_allowed=false`는 그대로다. 사용자가 확인하는 **모의 실행 권한**과 연구 통과·실전 배포 자격을 구분한다. 기존 관찰 전용 실행기의 모든 주문 차단도 그대로 유지한다.

다른 Python 코드가 내부 객체를 임의로 변조하는 상황까지 막는 운영체제 보안 장벽은 아니다. 이 앱에서 제공하는 주문 진입점과 실수로 켜질 수 있는 기존 경로를 차단한 것이다.
