# 관심종목 · 자동매매

현재 범위는 **GUI를 켜 두고 감시하며, 조건 또는 외부 신호별 주문을 한 번 시도하는 MVP**다.
기본은 모의투자다. 실전은 [환경 선택과 안전장치](trading-modes.md)를 거쳐 별도로 활성화하며 실제 자금을 사용한다.
수동 조건은 현재가 지정가, 명시적으로 허용한 외부 신호는 국내 시장가도 지원한다.
자동 재주문, 전략 수익성 보장, OS 백그라운드 서비스는 포함하지 않는다. 실전 API 접수·체결은 미검증이다.

## 화면에서 사용하기

1. `uv sync --extra gui` 후 `DockDack.vbs`를 실행하거나 `uv run --extra gui dockdack-gui`를 실행한다.
2. 왼쪽 **관심종목 · 자동매매** 버튼을 누른다. 기존 거래 화면의 조회/주문은 이 창이 열린 동안 일시적으로 잠긴다.
3. 기본 관심종목은 삼성전자, SK하이닉스, AAPL, GOOGL이다. 코드/티커를 입력해 추가할 수 있다.
4. 조회할 N을 입력하고 **선택 종목 기간 적용 → 전체 1회 조회**를 누른다.
   - N은 달력 일수가 아닌 거래일 개수이며 1~1000일을 지원한다.
   - 종목별 현재가, 통화, 조회시각과 수정주가 일봉 OHLCV를 보여 준다.
   - 180봉까지는 캔들, 그보다 긴 기간은 종가선으로 표시한다. 거래량과 마우스 상세 값도 제공한다.
   - `일봉 데이터` 탭에서 날짜별 시가·고가·저가·종가·거래량을 확인할 수 있다.
   - 신규상장 등으로 데이터가 부족하면 `실제 개수/요청 개수`를 표시하며 값을 만들어 채우지 않는다.
5. 종목을 선택한 뒤 트리거, 매수/매도, 수량, **주문금액 상한**을 직접 입력해 규칙을 등록한다.
   - 가격과 금액 상한의 단위는 국내 KRW, 미국 USD다.
   - 종목을 바꾸면 가격과 금액 상한을 0으로 초기화해 다시 입력하도록 한다.
6. 조회만 원하면 **감시 시작 (조회만)**을 누른다. 아직 주문은 전송하지 않는다.
7. 자동 주문을 원하면 **자동주문 켜기 (ON)**를 누르고 규칙 목록을 확인한다.
   한 번 확인하면 전체 조회 성공 후 ON이 된다. 조회 중에도 누를 수 있고, 감시가 꺼져 있으면 조회부터 시작한다.
   OFF로 예약을 취소할 수 있으며 전체 조회나 잔고/사용 중인 신호·선정 확인에 실패하면 OFF를 유지한다.
   확인 후에는 조건 충족 시 개별 주문 확인창 없이 선택한 환경에 주문을 전송한다.
8. **감시·주문 중지**로 다음 주문 전송을 차단한다. 이미 전송 중이거나 접수된 주문은 자동 취소되지 않는다.

앱을 닫으면 감시도 끝난다. 창을 다시 열거나 앱을 재시작하면 자동주문은 항상 OFF다.
기본 조회 간격은 30초이며, 15초~1시간으로 설정할 수 있다. 한 주기가 끝난 뒤 설정 간격을 기다린다.
API 호출 간격을 지키므로 관심종목 수가 많으면 한 주기에 시간이 더 걸린다. 최대 500종목을 지원한다.
**거래대금 TOP100 추가**로 한국·미국 각각 100종목을 등록할 수 있다. 차트 JSON 내보내기와 외부 모델의
buy/sell/hold 신호 연동은 [외부 신호 연결](external-signals.md)을 참고한다. 외부 신호 모드와 수동 트리거 모드는 분리된다.
실시간 WebSocket 감시가 아닌 REST 주기 조회이므로 조회 사이에 잠깐 발생한 조건은 놓칠 수 있다.
시장별 개장·정시 재선정, 종목별 연속 내보내기, 내장 테스트 신호기 사용법은 [지속 감시 운영 안내](server-mode.md)에 정리했다.

## 트리거의 정확한 의미

| 조건 | 판단 기준 |
| --- | --- |
| 현재가 ≥ 지정 가격 | 조회한 현재가가 입력 가격 이상 |
| 현재가 ≤ 지정 가격 | 조회한 현재가가 입력 가격 이하 |
| 현재가 ≥ N일 이동평균 | 현재가가 이전 N개 완료일 일봉 종가의 단순평균 이상 |
| 현재가 ≤ N일 이동평균 | 현재가가 이전 N개 완료일 일봉 종가의 단순평균 이하 |

이는 **수준 비교**이며, 직전에는 아래였다가 위로 바뀌는 교차/돌파 이벤트를 뜻하지 않는다.
시작할 때 이미 조건이 맞으면 첫 평가에서도 충족된다. 이동평균 N은 차트 표시 기간과 독립적이며,
계산에 필요한 일봉은 추가로 조회한다. 거래소 현지 날짜의 당일 봉은 계산에서 제외한다.
완료된 과거 일봉은 SQLite에 영구 저장해 재시작 후에도 계산에 사용한다. 처음 또는 기간 확대 시 필요한 N개를 받으며,
이후 장중에는 당일 봉만 5분 간격으로 재조회한다. 날짜가 바뀌거나 며칠 중단했다면 누락 거래일과 소수의 겹치는 봉만 받는다.
완료 봉의 수정주가 변경이 감지되면 저장 기간 전체를 재동기화한다. 과거 전체를 매번 검사하는 것은 아니다.
당일 봉의 실제 갱신은 5분 경과 후 다음 순회 시점이므로 요청 지연만큼 더 늦어질 수 있다.
API 응답은 페이지 단위여서 과거 봉이 함께 포함될 수 있다. '당일만 갱신'은 로컬 병합 범위이며 장중 일봉 요청을 없애는 의미는 아니다.
저장된 현재가는 재시작 직후 표시용이며 주문 판단에는 새로 조회한 시세를 사용한다.
현재가 조회시각은 거래소 체결시각이 아니며 API 시세가 지연될 수 있다.

## 주문 전 안전 검사

- 선택한 환경과 API 주소·키·기록 DB를 재확인한다. 실전은 별도 키, 허용 설정, 세션 위험 확인이 필요하다.
- 종목·시장·거래소·통화가 조회 결과와 일치해야 한다.
- 최근 일봉이 7일 넘게 오래되었거나 데이터가 없으면 보류한다.
- 거래일 캘린더의 정규장에만 전송한다. 보통 국내 09:00~15:30, 미국 뉴욕 현지 09:30~16:00이며 서머타임을 반영한다.
  휴장·조기폐장·확인된 특별 일정을 반영하고 캘린더 오류는 차단한다. 미래 임시 일정은 별도 점검해야 한다.
  특히 2026-11-19 국내 특별 개장시간은 확인 전 차단한다. [일정 범위와 제약](server-mode.md#거래일과-정시-재선정)을 참고한다.
- 미체결 또는 접수 여부가 불명확한 이전 주문이 있으면 같은 종목의 새 주문을 막는다.
- 이미 보유한 종목의 추가 자동매수, 매도 가능 수량을 넘는 매도, 공매도는 지원하지 않는다.
- 예상 주문금액은 규칙의 상한 이하여야 한다. 매수 시 주문가능금액에 1% 여유도 요구한다.
  실제 수수료·증거금과 주문 가능 여부는 증권사가 최종 판단한다.
- 잔고·미체결 조회 후 현재가를 다시 받아 조건을 재평가한다. 미국 현재가 지정가는 API 가격 단위에 맞춰
  매수는 내림, 매도는 올림한다($1 이상 소수 2자리, 미만 소수 4자리). 주식 **수량**은 바뀌지 않는다.
  변경된 지정가에도 금액 상한을 다시 적용하고 참조 시세와 실제 전송 지정가를 주문 로그에 구분한다.
  직접 입력한 지정가는 임의 반올림하지 않고 지원하지 않는 가격이면 전송 전에 거절한다.
  국내 시장가는 단가 없이 보낸다. 시장가 금액 상한은 **현재가 기준 추정치**이므로 실제 체결 총액을 보장하지 않는다.
- 테스트 매도의 +1% 익절 / -0.8% 손절 조건은 신호 생성 때뿐 아니라 주문 직전 잔고의 평균 매입가로 다시 검사한다.
  지정가 미체결, 시장가 체결가격, 수수료·세금으로 인해 실제 순수익 +1%나 손실 -0.8% 이내를 보장하지 않는다.
- 빈/비정상 응답, 불완전한 연속조회 결과를 근거로 주문하지 않는다. 조회 페이지 상한을 넘기면 오류로 처리한다.

## 1회성 규칙과 주문 기록

규칙은 **한 번 주문을 시도하면 소모**된다. 주문 거절, 타임아웃, 장 종료 오류에도 같은 규칙으로 자동 재시도하지 않는다.
주문 직전 SQLite에 전송 의도를 먼저 기록한다. 재시작하거나 같은 DB를 사용하는 창이 동시에 실행되어도
이미 시도한 규칙을 다시 전송하지 않는다. 다만 증권사 측의 exactly-once 전송 보장은 아니다.

접수 후에는 당일 체결 내역으로 체결 또는 취소를 확인한다. 미체결 목록에서 사라졌다는 이유만으로 체결로 판단하지 않는다.
이전 날짜의 주문, 응답이 끊겨 주문번호를 모르는 주문은 자동으로 체결을 추정하지 않는다.
이때 자동주문이 꺼지거나 해당 종목이 차단된다. 영웅문에서 내역을 직접 확인하고 필요한 잔여 주문을 정리한 뒤
**내역 확인 후 종목 차단 해제**를 사용한다. 이 작업도 기존 규칙을 재실행 가능 상태로 되돌리지는 않는다.

수동 조건으로 다시 거래하려면 확인 후 새 규칙을 등록해야 한다. 외부 모드는 새 데이터에 대한 새로운 판단이 새 규칙을 만든다.
같은 판단/주문 시도는 재전송하지 않는다. 대기 중인 동일 수동 규칙의 중복 등록은 막는다.
미확정/미체결 주문이 있는 종목은 확인 전 관심종목에서 제외할 수 없다.

저장 위치는 프로젝트의 `.dockdack/watchlist.sqlite3`이며 관심종목, 과거 일봉, 규칙, 시세 캐시, 주문 시도,
활동 기록, 순위 재선정 이력과 테스트 신호 결정을 저장한다.
API 키는 저장하지 않는다. `.dockdack/`와 `.env`는 Git에서 제외한다.
**DB를 지우거나 여러 프로젝트/PC에 복사해 동시에 실행하면 이력 기반 중복 방지가 적용되지 않으므로 피한다.**
같은 DB에서 모의 계좌 키를 바꿔 사용하는 방식도 지원하지 않는다. 기존 주문을 먼저 확인하고 별도로 관리해야 한다.

## 코드에서 사용하기

```python
from decimal import Decimal
from dockdack.autotrade import AutoTrader
from dockdack.gui_service import TradingService
from dockdack.watchlist import TriggerRule, WatchItem, default_store

service = TradingService()                 # 모의투자 전용
store = default_store()
item = WatchItem(service.resolve("005930"), "삼성전자", days=60)
store.save_item(item)
rule = TriggerRule.create(
    item, kind="price_le", side="buy",
    quantity=int(input("수량: ")),
    threshold=Decimal(input("매수 조건 가격 (KRW): ")),
    max_notional=Decimal(input("주문금액 상한 (KRW): ")),
)
store.add_rule(rule)
engine = AutoTrader(service, store)
results = engine.poll()                   # 데이터 조회/조건 평가만. 주문 없음.
# 실제 모의 자동주문을 허용할 때만 별도 사용자 확인 후:
# engine.enable_orders("DEMO_AUTOTRADE")
# for results in engine.run_forever(interval_seconds=30):
#     ...
# 다른 제어 스레드에서 engine.stop()으로 중지
```

현재가는 `service.quote(instrument)`, 일봉은 `service.history(instrument, days)` 또는
`KiwoomBroker.daily_history(market, symbol, exchange=..., days=...)`로 독립적으로 사용할 수 있다.
`evaluate_trigger(rule, snapshot, now)`는 HTTP 전송과 분리된 평가 함수다. 새 조건은 이 함수와 `TriggerKind`를 확장한다.
