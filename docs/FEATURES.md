# DockDack 0.2 기능 안내

이 문서는 2026-09-30 현재 `mark_1` 개발 브랜치의 **구현된 기능**을 화면과 실행 경로별로 설명한다. 앱 버전 0.2(`pyproject.toml`의 0.2.0)와 `mark1.n prototype` 모델 번호는 별개다. 모델을 골랐다는 사실, 신호를 받았다는 사실, 주문이 접수됐다는 사실, 체결됐다는 사실은 서로 다른 상태다. 모의 연결이나 자동 테스트는 수익성·실거래 검증이 아니다.

## 한눈에 보는 범위

| 영역 | 현재 제공하는 것 | 제공하지 않는 것 |
| --- | --- | --- |
| 기본 데스크 | Windows PySide6 통합 화면, 국내·미국 관심종목/계좌/체결/일지/AI/고급설정 | 앱을 닫아도 계속 작동하는 클라우드 서비스 |
| 신호 | 제공 prototype의 독립 프로세스 추론, 외부 JSON 신호, 수동 규칙·호환 테스트기 | 모델 자동 재학습·수익성 자동 승인 |
| 주문 | 명시적 ON 이후 시장·시세·잔고·신호·상한·중복 검사를 통과한 주문 전송 | ON 즉시 주문, 접수 즉시 체결, OFF 시 기존 주문 자동 취소 |
| 기록 | 계정별 주문·체결·모델 lot와 조회 이력, 확인 근거에 따른 실현손익 | 증권사 계좌 전체의 세후 손익·세금 신고 |
| 연구 | 일봉 수집·정제·학습·백테스트·번들 검증과 국내 모의 시세의 완료 분봉 수집·오프라인 후보 평가를 별도 명령으로 수행 | GUI에서 모든 모델을 학습·배포하는 버튼, 2026-09-29 분봉 재학습 번들의 자동주문 연결, 헤지 두 다리 주문, 시간대 미확인 미국 분봉의 임의 변환 |

일반 화면과 개발자 도구를 혼동하지 않도록 아래에 각각 구분했다. 실행과 키 설정은 [README](../README.md) 및 [개발 안내](development.md), 화면 조작 예시는 [GUI 안내](gui.md)를 참고한다.

## 기본 데스크와 운영 상태

주탭은 **관심종목 → 보유종목 → 매매일지 → 주문·체결 → AI 추론 모델 → 고급설정** 순서다. `DockDack.vbs` 또는 `dockdack-gui`로 연다. 처음에는 모의 환경, 감시 OFF, 자동주문 OFF다. 계정별 설정을 불러와도 감시/주문 허용·실전 계정 선택을 자동 복원하지 않는다.

| 위치/조작 | 실제 동작과 조건 |
| --- | --- |
| 상단 자동주문 상태 | 한 상태 버튼으로 ON/OFF를 바꾼다. ON 확인창은 환경을 제목에 구분하고 `자동매매를 켜시겠습니까?` 한 문장과 예/아니오만 보여준다(기본 아니오). 사용자 확인과 전체 관심종목·잔고 검사는 그대로 필요하며, 조회 중이면 `ON · 준비 중` 예약 상태를 표시한다. 실패하면 OFF를 유지한다. OFF는 예약·새 주문·반복 감시를 중지하지만 이미 접수된 주문은 취소하지 않는다. |
| 상단 AI 모델 카드 | 선택한 모델 수를 큰 숫자로 표시한다. 실제 작업자 연결 성공 수가 아니며, 확인된 연결 실패는 점검 표시·툴팁으로 구분한다. |
| 상단 최근 조회 카드 | 자동주문 상태와 AI 모델 수 사이에서 최근 종목·시세와 의미 있는 모델 판단 최대 3개 및 나머지 개수를 보여준다. 전체 모델별 내용은 툴팁으로 확인한다. 장중 장벽 모델은 **같은 종목·같은 시세**에 대한 활성 모델 판단이 모두 완료된 후에만 평균을 갱신한다. 새 조회가 일부만 끝났으면 직전 완료값을 유지한다. 서로 다른 목표의 확률·일봉 대리점수·장전 점수는 평균에 섞지 않는다. |
| 시장 상태 | 제목 옆에 한국·미국의 장전/장중/마감/휴장/확인 필요를 표시한다. 현지 일정·미국 서머타임을 반영하지만 브로커 자체의 운영 장애까지 보장하지 않는다. |
| 환경 선택 | 모의·실전의 키, 서비스와 장부 범위를 분리한다. 전환하면 감시·주문을 중지한다. 실전은 별도 키·권한·경고 확인이 필요하다. 제공 prototype 신호는 실전 환경에 연결하지 않는다. |
| 조회 전용 감시 | 고급설정에서 전체 1회 조회 또는 반복 감시를 시작한다. 순회 후 대기 시간은 종목별 갱신 주기가 아니다. 별도 ON을 하지 않으면 주문을 보내지 않는다. |
| 창 제어 | F11 전체화면, Esc 복원, 작은 화면에서 내부 스크롤을 제공한다. 창을 닫을 때 새 작업을 막고 작업자/추론 프로세스를 정리한다. 이미 접수된 주문 취소는 아니다. |

## 관심종목·차트

**관심종목** 탭은 한국·미국을 분리하고, 종목명/코드, 기존 Mark1.0–1.28의 선택 모델별 판단, **현재가·조회**를 표의 오른쪽에 둔다. 새 분봉 모델 Mark1.29–1.37의 후보·보류·원인은 AI 화면의 선택 종목 결과와 최근 조회 요약에서 확인한다. 연구 전용 Mark1.38–1.44는 이 가로표에 판단 열을 만들지 않는다. 통화는 시장 탭과 툴팁에서 확인하며 가격 셀은 한 줄 숫자로 표시한다. 판단 전 또는 근거가 없으면 `—`만 표시한다. 현재가·조회 시각·모델 점수는 시세/신호의 상태이며 체결 가격이 아니다.

| 기능 | 동작과 제약 |
| --- | --- |
| 시장별 종합 TOP100 | 거래대금·거래량·상승률·하락률 상위에서 각 20개, 미국은 시가총액 상위 20개도 모아 중복을 제거한다. 공식 예제에서 국내 시가총액 상위 전용 순위 API를 확인하지 못해 이번 구현에서는 해당 범주를 적용하지 않는다. 각 시장의 남는 자리는 거래대금 상위 100개로 채워 **확인된 일반 기업 보통주 정확히 100개**를 확정한다. ETF/ETN/펀드/우선주/리츠/스팩/예탁증서와 분류 불명 종목은 제외한다. |
| 선정 시각·복구 | 개장 10분 전, 실제 개장 시각(미국 09:30 포함), 정규장 현지 매 정시에 재선정한다. 휴장·조기 폐장, 지난 시점 따라잡기, 실패 재시도와 느린 응답의 덮어쓰기 방지를 적용한다. 실시간 순위 구독은 아니다. |
| 복합 순위 실패 | 필수 범주나 적격 100종목을 확인하지 못하면 불완전한 새 순위를 적용하지 않고 이전 완전한 순위를 유지한다. |
| 순위 밖 기록 | 수동 등록·기존 보유·미확정 주문·지난 판단 이력은 삭제하지 않는다. 완전한 TOP100 밖 종목은 활성 목록에서 제외하거나 비활성 이력 행으로 남긴다. 순위 밖 보유 매도와 미확정 주문 대조는 계속한다. |
| 종목 관리 | 고급설정에서 코드/티커와 거래소를 확인해 추가·제외하고 조회 일봉 수(1–1000)를 지정한다. 모델 입력에는 최소 31일을 요구한다. 종목을 제외해도 보유·주문 기록과 이미 접수된 주문은 지워지지 않는다. |
| 조회와 캐시 | 현재가와 최근 일봉을 순차 조회한다. SQLite 과거 봉 캐시를 재사용하며 누락·수정된 완료 봉은 다시 맞춘다. 대량 학습 DB 수집과는 다른 경로다. |
| 차트·봉 표 | 선택 종목의 OHLC·거래량, 긴 구간의 종가선과 봉 상세 마우스 확인을 제공한다. 차트 상단에는 현재가와 직전 완료 종가 대비 변동률을 표시하고 근거가 없으면 `—`로 둔다. 좁은 창에서는 모델 열을 표 내부에서 가로 스크롤해 차트 공간을 유지한다. |
| 차트 JSON | 고급설정에서 전체/종목별 차트를 내보낸다. 외부 모드 감시 중에는 각 종목 조회 직후 개별 파일, 순회 후 전체 파일을 갱신한다. 경로·고유 `export_id`는 [신호 계약](external-signals.md)을 따른다. 내보내기는 주문 허용이 아니다. |

## AI 추론 모델

주탭 **AI 추론 모델**에는 `모델 선택`과 `모델 성과` 두 하위탭이 있다. 모델 선택 카드는 **장중·확률 3개 / 장전·점수 10개 / 장중·일봉 대리 10개 / 장중·목표가·보유기간 연구 6개 / 일봉 학습→5분봉 추론 9개 / 인버스 헤지 연구 7개** 섹션으로 구분하고 이름·학습 방식·출력 단위·매도 방식을 분리해서 표시한다. 모델별 선택과 `전체 선택`·`선택 해제`는 설정만 바꾸고 감시·주문을 켜지 않는다. 같은 종목을 여러 주문 가능 모델이 독립적으로 판단·매수할 수 있다. 관심종목 가로표는 기존 Mark1.0–1.28의 OFF 열을 숨기고 ON 열만 표시하며 장중 조회 모델 열 뒤에 장전 모델 열, 끝에 현재가·조회 열을 둔다. 새 분봉 모델의 후보·보류·원인은 AI 화면의 선택 종목 결과와 최근 조회 요약에서 확인한다. 선택은 조회나 주문 ON이 아니다. 감시·주문·조회 작업 중에는 선택과 비중 입력을 잠근다.

제공 prototype은 **모의 전용**이다. 주문 가능 모델은 독립 출처 ID, JSON 신호와 전략 lot을 사용한다. 기존 Mark1.0–1.28은 별도 추론 프로세스이고, Mark1.29–1.37은 앱 감시 작업자에서 모의 시세·계좌 근거를 읽어 추론하되 직접 주문하지 않는다. 인버스 헤지 7개는 고정된 연구·주문 보류 상태만 표시하고 매수 비중·주문 신호를 만들지 않는다. 앱은 신호의 출처·종목·만료·재전송·출력 파일을 검사하고, 개별 모델 오류를 다른 모델과 구분해 보류한다. 장전 모델은 개장 10분 전 종합 TOP100과 완료 30봉으로 후보를 동결한 뒤 개장 후 최신 시세·잔고·주문 지정가를 재검사한다. 기존 장중 조회 모델은 주문 전 현재가와 실제 지정가로 재추론한다. 최초 BUY 하나만으로 계속 주문하지 않는다.

Mark1.4는 예외적으로 내부 장전 점수의 종목 집합을 기존 **거래량 상위 100개**에서 만든다. 다만 화면과 실행기의 조회·신호·주문 대상은 복합 TOP100뿐이다. 거래량 후보가 복합 순위 밖이면 그 후보는 실제 신호·주문으로 이어지지 않는다. 숨은 종목을 주문하려고 감시 범위를 100개 밖으로 넓히지 않는다.

Mark1.0–1.2만 장벽 성공 **추정확률**이다. Mark1.13–1.22는 과거 분봉/틱의 장중 선후 경로가 아니라 **다음 세션의 관측 시가에서 당일 전체 고가 +1% 도달·저가 −0.9% 미도달**을 정답으로 학습한 일봉 대리모델이다. 실제 조회 시에는 그 시가 대신 현재가를 입력하므로 0–1 출력과 `0.5 초과` 후보 기준은 검증된 장중 성공확률·수익률이 아니다. 국내·미국 각각 학습한 20개 체크포인트와 특징별 실제 참조 구간, 봉인 검사 및 미검증 범위는 [장중 조회용 일봉 대리모델](mark1-intraday-proxy.md)에 기록한다. Mark1.23–1.28의 별도 대리사건과 기간 매도는 [목표가·보유기간 방법](mark1-target-horizon-methods.md)에 기록한다. 기존 3개 장벽 확률의 상단 평균에 어느 대리점수도 섞지 않는다.

장전 출력도 서로 단위가 다른 점수·회귀값·비중이며 확률로 바꾸거나 합산하지 않는다. Mark1.6의 0–1 점수도 보정된 승률이 아니다. 장전 당일형과 기간형의 매도는 가격이 목표에 도달했다는 뜻이 아니라 **확인된 자기 lot의 기간 조건**이다. 장기형은 체결 관측이 늦으면 예정일도 늦어질 수 있다. Mark1.11/1.12의 과거 연구가 가정한 비중복 진입·마지막 날 종가 청산과 운영 방식이 다르다.

처음 설치해 저장된 선택이 없는 **모의 계정**은 Mark1.0–1.44 전체 45개를 초기 선택한다. `전체 선택`과 `선택 해제`는 모의 환경에서 설정을 일괄 변경하며 감시·자동주문을 시작하지 않는다. 기존 계정에 저장된 유효한 선택은 그대로 복원하고, 사용자가 해제한 모델을 임의로 다시 켜지 않는다. **실전 환경은 prototype 초기 선택이 없다.** 현재는 계정별 화면 설정으로 선택과 모델별 비중을 저장하며 명시적 명령줄 모델 지정이 저장 선택보다 우선한다. 모델 해제 뒤에도 이미 확인된 보유 lot의 출처·매도 조건은 남지만, 다시 감시/주문 ON을 하기 전에는 새 자동매도가 실행되지 않는다.

Mark1.29–1.37의 가중치 9개는 40개 국내 종목에서 2026-08-21까지의 완료 일봉 53,807개로만 학습했다. 한 종목 안에서는 기업행사 경계를 건너지 않는 단일 연속 구간만 사용했고, 품질 문제 266행을 제외했다. 검증 구간의 상위 20% 임계값은 후보 빈도 조건이지 분봉 수익성 최적화가 아니다. 40종목을 2026년 최근 거래대금으로 골랐으므로 과거 2021–25년 평가에 미래 정보에 따른 종목 선정·생존 편향이 있다. 일봉 보유 구간의 과거 대리평가는 시장 전체 수익이나 실제 분봉 손익이 아니다. 운영 입력은 키움 **모의** API의 당일 완료 5분봉이며 가중치를 분봉으로 재학습하지 않는다. 신호봉 뒤 최소 15분 지연, 같은 세션에서 시한 내 매도 가능 여부, 학습 종목 여부와 번들 해시를 검사한다. 학습 대상 40종목 밖에는 분봉 조회를 요청하지 않고 보류한다. 9개 모델은 종목별·완료 5분 구간별 공유 캐시를 필요한 때만 읽고, 연속 봉·시각·영수증·신선도 검증 실패 시 신호를 보류한다. 봉 게시 지연·조회 실패는 같은 완료 슬롯에서 20초 이상 간격으로 최대 3회 시도한다. 필요한 연속 봉이 최신 페이지와 캐시에 부족할 때만 페이지 상한을 1→2→5로 늘리며 API에 없는 시각 커서를 만들지 않는다. 분봉 수익성·체결은 검증되지 않았다. 이전의 분봉 재학습 번들은 별도 오프라인 연구 결과이며 이 9개 모델에 섞지 않는다.

Mark1.38–1.44는 7개 두 다리 가설의 연구 상태만 선택 화면에 연결한다. 종목·KOSPI200 현물지수·인버스 ETF의 과거 완료 5분봉으로 비용과 지연을 반영한 평가에서 보수 비용 조건의 후보가 모두 보류됐다. 현물지수 숏은 거래할 수 있는 ETF와 같지 않고, 주식·ETF 두 주문을 원자적으로 보장할 수도 없다. 따라서 연구 보고서의 `pass`는 이익 또는 주문 적격을 뜻하지 않으며 7개 모두 모의·실전 주문 의도를 만들지 않는다. [분봉·인버스 헤지 연구](minute-research.md)에 자료와 제한을 기록한다.

### 모델별 1회 매수 비중

`모델 선택` 카드의 `1회 매수`에서 주문 가능 모델마다 **시장별 평가자산의 0.01–100%**를 0.01% 단위로 정한다(기존 모델 초기값 10%, Mark1.29–1.37 초기값 1%). 연구 전용 Mark1.38–1.44에는 매수 비중 입력이 없다. 비중은 한 번의 주문 **예산 상한**이지 권장 비중이나 하루 누적 한도가 아니다. 사용자의 변경은 계정별 v4 화면 설정에 저장·복원된다. v1–v3의 공통 `buy_percent`는 최초 모델별 값으로 승계한다. 제공 모델 주문에는 해당 모델 값, 기타 외부/구형 신호에는 고급설정의 `기타 신호 1회 매수 비중`을 사용한다. Mark1.8의 동결 학습 비중이 더 낮으면 더 낮은 값이 적용된다. 모든 경우 정수 주식 수, 시장별 수량·금액 상한, 확인된 가용액과 1% 수수료 여유를 다시 적용하며 0주면 주문하지 않는다. 감시·작업·주문 준비 중에는 입력을 잠그고 변경 시 기존 감시·주문을 중지한 뒤 정책을 갱신한다.

같은 화면 상단의 비중 입력과 `일괄 적용`은 **선택 여부와 관계없이 Mark1.0–1.37 전체 38개**의 개별 `1회 매수` 값을 바꾼다. 연구 전용 Mark1.38–1.44와 고급설정의 기타 신호 기본 비중은 대상이 아니다. 범위는 0.01–100%, 소수 둘째 자리까지이며 일괄 입력 초기값은 1%다. 숫자만 입력해도 자동 적용되지 않고 버튼을 눌러야 정책과 모델별 저장값을 한 번 갱신한다. 모델 체크 상태·스크롤 위치를 유지하고 감시·주문을 시작하지 않는다. 적용 후 카드마다 다른 값으로 다시 조정할 수 있다. 감시·조회·주문 준비·확인·환경 변경 중과 실전 환경에는 개별·일괄 비중 편집을 잠근다.

### 모델 성과

같은 AI 화면의 `모델 성과`는 **현재 계정 장부의 확인된 매도 체결**을 원매수 모델별로 집계한다. 국내 KRW/미국 USD와 모의/실전 계정은 분리한다. 실현 수익률은 확인된 매도분의 `실현손익 ÷ 매수원가`이며 미매도 평가손익·수수료·세금은 포함하지 않는다. 매도 체결이 없으면 0%라고 쓰지 않고 `매도 체결 없음`, 근거가 모자라면 `확인 필요`로 둔다. 출처 미확인·수동 거래는 모델 성과에 가짜 모델로 끼워 넣지 않는다. 읽기·재계산만으로 API 주문이나 환경 변경을 시작하지 않는다.

## 주문 크기·실행 통제

자동주문은 **상단 ON**, 현재 거래 환경, 정규장 여부, 유효한 신호/수동 규칙, 적격 보통주, 최신 시세·잔고·미체결, 시장별 주문당 상한과 모델별 보유 근거를 모두 재검사한 후에만 전송한다. 실제 주문은 최근 현재가에서 호가 단위에 맞춘 **지정가**이며 현재가 또는 목표가 체결을 보장하지 않는다.

## 보유종목과 모델별 매도

**보유종목**은 국내·미국의 수량, 평균 매수가, 현재가, 평가금액·평가손익·수익률, 매도가능수량, 현금·예수금과 주문가능액을 구분해 보여준다. 앱 시작 시 비동기로 조회하며 탭 이동·재클릭 또는 새로고침에서도 재조회한다. 시장별 최소 60초 호출 간격과 진행 중 요청 예약을 지키므로 클릭 즉시 새 값이 보이지 않을 수 있다. 탭에 머무는 것만으로 반복 API 조회하지 않는다.

같은 종목을 여러 모델이 사도 브로커 잔고는 합산 수량인 반면, 앱은 **확인된 체결**을 모델·매수 건별 가상 lot으로 구분한다. 장중 Mark1.0–1.2·1.13–1.22는 각 lot의 매수 기준가로 목표가를 계산하고, 장전 모델은 자기 lot의 종료 시각을 계산한다. Mark1.23–1.28은 자기 lot의 매수 기준가에서 모델별 +2–4% 목표가를 먼저 적용하고, 미도달 시 체결 관측 세션을 1일째로 세어 10/20번째 거래 세션 **마감 5분 전부터** 매도를 시도한다. 손절은 추가하지 않는다. 당일형은 자기 lot만 마감 5분 전부터, 3/5세션형은 체결 관측일부터 센 해당 거래 세션 정규장 중에 가격과 무관하게 매도를 시도한다. 수동·출처 미확인·다른 모델 보유분을 계좌 전체로 청산하지 않는다.

보유 매도 조건은 일반 관심종목보다 먼저 점검하고 순회 중에도 재점검한다. 전송 직전까지 미체결 없음, 실제 보유·매도가능수량과 신선한 계좌 근거를 확인한다. 원매수 모델·전량 체결수량이 확인된 **모의 Mark1 BUY**에 증권사의 실제 평균 체결가 근거가 없으면, 주문 당시 저장된 참고 시세를 **추정 매도 기준**으로만 쓸 수 있다. 이 값은 실제 주문 지정가나 체결가가 아니며, 확정 원가·모델 성과·실현손익으로 승격하지 않는다. 실전 환경에는 적용하지 않고 예수금 전후 차액으로 원가를 역산하지도 않는다. `accepted`/`unknown` 등 체결 미확정, 추가 체결이 가능한 부분체결, 모델 출처·확정 수량 또는 브로커 보유량 대조가 불명확한 건은 계속 **모델별 자동매도**를 보류한다. 다만 현재 브로커 보유수량과 앱 장부 수량이 같아도 앱 밖 거래가 없었다는 증거는 아니다. 같은 모의 계좌에서 다른 앱·수동 매매를 섞어 해당 종목을 매도·재매수하면 모델 자동매도가 그 보유분을 오인할 수 있다. 국내 보유도 출처가 없으면 모델에 임의 배정하거나 장 시작에 일괄매도하지 않는다. 기존 일반 보유분의 별도 목표가가 없을 때는 기본 +1%/−0.8% 자동매도가 별도로 적용될 수 있다. 기간 매도 예정일은 체결 약속이 아니다.

미국 보유종목의 `원화` 토글은 유효한 ECB 일별 USD/KRW **참고환율**로 화면의 USD 금액·가격을 KRW로 환산한다. 마지막 유효 환율을 OFF/ON 간 재사용하고 `환율 갱신`에서만 새 고시를 요청한다. 환율 오류·오래된/형식이 잘못된 고시에는 USD 또는 직전 유효 표시를 유지한다. 원본 USD·주문·DB는 바꾸지 않으며 실제 환전가도 아니다.

Mark1.29–1.37의 +3% 익절·−2% 손절과 15/30/60분 시한은 각 모델이 **체결로 확인한 자기 lot**의 매수 기준가·체결 관측 시각에서 계산한다. 정규장 마지막 5분에는 시한 전이라도 청산 후보를 낸다. 개장 전·장 종료 후·휴장일에 처음 체결을 관측한 경우에는 이전 체결시각을 추정하지 않고, 관측 시각부터 보유 시한이 지난 이후 첫 정규장 시점부터 기간 매도 후보를 낸다. 보유 화면의 `기간 매도 예정`은 거래소 현지 시각 `YYYY-MM-DD HH:MM`으로 표시하며 과거 시각으로 당겨 표시하지 않는다. 이는 REST 조회 시점의 조건부 주문 시도이며 목표 가격이나 마감 전 체결을 보장하지 않는다. 출처·체결·보유수량이 불확실하면 다른 Mark1과 동일하게 모델별 자동매도를 보류한다.

| 위치 | 기능과 한계 |

| 주문·체결 | 이 앱 장부의 시도·미전송·거절·접수·미확정·부분체결·취소·완료를 구분한다. 주문번호·방향·종목·수량·조회일의 근거가 맞는 증권사 체결가만 보완한다. 모의 Mark1의 참고 시세 기반 추정 매도 기준은 체결가 칸을 채우지 않는다. |
| 실현손익 | 모델 lot의 확인 원가, 일반 매도의 FIFO 원가를 사용한다. 화면 표시 건수와 별개로 전체 저장 장부를 계산한다. 추정 매도 기준을 확정 원가로 간주하지 않으며 체결가/원가가 없으면 `미확인`이다. 수수료·세금·다른 앱의 거래는 포함하지 않는다. |

상단의 **고급설정**은 상시 보이는 주탭이다. 탭을 여는 것만으로 신호 방식·감시·주문 권한이 바뀌지 않는다.

| 하위탭/도구 | 역할 |
| --- | --- |
| 조회·감시 | 전체 1회 조회, 감시 시작/중지, 순회 후 대기, 종목 추가·제외, TOP100 재선정, 차트 JSON 내보내기와 화면 조회 설정. |
| 공통 주문·연결 | 시장별 수량/금액 상한, `기타 신호 1회 매수 비중`, JSON 입력·출력 경로와 파일 형식 검사/1회 읽기·폴더 열기. 파일 형식 검사는 주문을 만들지 않는다. 1회 읽기는 후보를 접수할 수 있지만 자동주문을 ON으로 바꾸지 않는다. |
| 신호 방식·구형 모델 | 외부 AI 신호와 수동 규칙 모드를 구분한다. 모든 모델을 끈다고 수동 규칙이 자동 실행되지는 않는다. 구형 내장 LSTM30은 현재 제공 prototype과 별개다. |
| 트리거 규칙 | 수동 가격/이동평균 매수·매도 규칙과 비활성화/확인 필요 상태를 관리한다. |
| 직접 신호기 | 사용자 정의 `source_id`·JSON 경로를 등록한다. 중복 출처/경로·연결 수 상한을 검사하고 BUY/SELL/HOLD의 생성·만료 시각과 재전송을 검증한다. 외부 코드 자체를 JSON에서 실행하지 않는다. |
| 모의 테스트 신호기 | 무작위 매수와 기존 일반 보유분 목표가를 실험하는 별도 모의 도구다. 학습 AI가 아니고 제공 모델/실전 경로와 동시에 쓰지 않는다. |
| 서버·감시 로그 | 운영·조회·신호 로그를 나누어 읽는다. heartbeat만으로 브로커 정상이나 체결을 단정하지 않는다. |

`python -m dockdack.gui` 수동 주문 창, `examples.run_lstm30_demo`/`run_lstm30_gui`와 초기 Mark1 전용 화면은 **기본 통합 GUI가 아닌 호환·연구 도구**다. 별도 수동창에는 시세/잔고/미체결/주문 확인이 있지만 현재 일반 화면의 AI 설정이나 모델별 lot와 같다고 간주하지 않는다.

## 터미널·Python API

`dockdack` 대화형 터미널은 종목 입력 후 시세·잔고·미체결·주문을 선택한다. `quote`, `balance`, `orders`는 일회성 조회이며 `buy`, `sell`은 종목·시장·거래소·정수 수량·주문 가격 방식을 지정한다. `--dry-run`과 최종 사용자 확인은 전송과 구분한다. 시장가 지원은 시장/모의 환경에 따라 다르다. 원주문 취소 요청은 별도 API/CLI 기능이지 자동주문 OFF의 부작용이 아니다. [터미널 사용법](terminal.md)

Python `KiwoomBroker`/HTTP 계층은 국내·미국 종목 검색, 시세·거래량/거래대금 순위, 일봉 페이지 조회, 계좌·미체결·체결 조회, 지정가/지원 시장가 주문·취소와 인증·호출 간격·연속 키를 다룬다. 저장 조건식의 WebSocket 조회는 선택적 `conditions` 의존성이 필요하며 GUI 조건식 편집기나 모든 종목의 틱 스트리밍이 아니다. 브로커 코드가 있다고 해서 모든 기능이 기본 화면 버튼에 있는 것은 아니다. [브로커 문서](kiwoom-broker.md)

## 데이터·학습·연구 도구

**일반 GUI의 최근 차트 캐시**와 **전 종목 학습용 일봉 DB**는 다르다. 별도 수집기는 API가 허용하는 국내·미국 OHLCV 이력을 SQLite에 적재하고, 임시 수집 세대·연속 키·날짜/OHLCV/종목 일관성을 검증한 뒤 정상 세대를 교체한다. 정제 도구는 원본을 덮어쓰지 않고 오류·저유동성 구간과 승인된 완료 30봉 학습창을 기록한다. 저유동성 검사는 실제 유통주식 수/free float 판별이 아니다. 현재 카탈로그에 없는 과거 상장폐지 종목까지 완전 수집했다고 주장하지 않는다. DB 스냅샷 ZIP·체크섬 포장, 차트 캐시 이전도 개발자 명령이다. [수집](daily-dataset.md) · [정제](dataset-cleaning.md)

## 저장·안전 경계

- `.env`의 비밀키, `.dockdack/` 운영 장부, `data/` 원본·정제 DB, `outputs/` 연구 결과와 계정별 경로를 혼동하거나 Git에 게시하지 않는다. `models/`의 동결 가중치는 원본 출처·해시 검사와 함께 사용한다.
- 장부 설정은 계정 범위별로 보존하지만 감시·자동주문 ON과 실전 환경을 자동 복원하지 않는다. 일반 GUI의 과거 `평가자산 비중으로 매수` 체크를 다시 노출하거나 저장된 OFF 값으로 고정수량 모드로 돌아가지 않는다.
- 결측 시세·환율·체결가·매수원가·거래 세션 또는 장부 불일치에 임의 값을 채우지 않는다. 표시는 `—`, `확인 필요`, 보류로 남긴다. 위의 모의 전량 체결 주문 참고가 예외는 추정 매도 기준에만 적용하며 확정 체결가·원가를 채우지 않는다.
- 현재 프로세스가 실행 중이어야 감시가 지속된다. 순차 조회와 API 제한 때문에 시장 전 종목의 실시간 동시 갱신이나 30초 내 전 종목 재조회는 제공하지 않는다.
- 제공 prototype은 모의 전용이다. 테스트의 가짜 응답, 연구 백테스트와 과거 일부 모의 관찰을 실전 체결·미래 수익 보증으로 읽지 않는다. 실제 계좌 주문 검증은 별도 승인과 기록이 필요하다.

검증 이력과 남은 문제는 [2026-09-28 감사 결과](audits/2026-09-28/findings.md), [수정·검증 기록](audits/2026-09-28/remediation.md), [개발일지](../DEVLOG.md)에 구분해 남긴다. 이 기능서는 **현재 구현의 위치·조건·한계**를 설명하며 삭제 승인이나 수익성 인증서가 아니다.
