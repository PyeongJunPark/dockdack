# 딥러닝용 일봉 정제 DB

원본 수집 DB를 수정하거나 삭제하지 않고 별도 SQLite DB를 만든다. 작업 브랜치는 `feat/data-collection`이다. 정제 과정은 증권사 API, 자동매매, 모델 학습을 실행하지 않는다.

## 고정 기준 v1

현재 DB에는 과거 유통주식수가 없으므로 **저유통주 자체가 아니라 저유동성 구간**을 거른다. 최신 상태로 종목의 과거 전체를 제거하지 않고, 각 입력 종료일 당시까지의 정보만 사용한다.

| 기준 | 국내 | 미국 |
|---|---:|---:|
| 최근 20거래일 거래대금 중앙값 | 10억 원 이상 | 100만 달러 이상 |
| 최근 20거래일 거래량 중앙값 | 1만 주 이상 | 1만 주 이상 |
| 최근 60거래일 거래량 양수 비율 | 95% 이상 | 95% 이상 |
| 최근 60거래일 연속 거래량 0 | 최대 2일 | 최대 2일 |

60개 연속 정상 거래일을 확인한 다음 입력 종료일의 유동성을 판정한다. 입력 종료일은 거래량이 양수여야 한다. 모든 입력 봉 각각이 거래대금 기준을 통과해야 한다는 뜻은 아니다. 정상적인 일시 무거래 봉은 그대로 유지하며 값을 채워 넣지 않는다.

입력은 연속된 예정 거래일의 정상 일봉 30개, 정답은 바로 다음 예정 거래일의 정상·양수 거래량 봉이다. 정답 봉의 거래대금이나 미래 수익률 크기로 샘플을 고르지 않는다. 기존 모델과 호환되는 `target_up`은 **다음 종가가 입력 종료일 종가보다 1% 이상 높은지**이며, 장중 고가 도달이나 손익절 선후관계가 아니다.

단, 정답 날짜가 누락되거나 무거래이면 샘플을 만들지 않으므로 **다음날 관측/거래 존재 여부에 따른 선택은 남는다**. 이를 미래 정보의 영향을 완전히 없앤 전체 투자 가능 표본이라고 해석하면 안 된다.

### 거래대금 단위

- 국내 `ka10081.trade_value`는 백만원이므로 ×1,000,000 하여 원화로 비교한다. [키움 공식 ka10081](https://openapi.kiwoom.com/m/guide/apiguide/07/ka10081)
- 미국 `usa06012.trade_value`는 이 수집 DB에서 USD 단위로 실측 확인했다. 공식 필드 설명의 단위 칸은 비어 있으므로 공식 보장과 구분한다. 결정적 200종목 최신 구간 표본에서 `거래대금/(종가×거래량)` 중앙값은 1.00023이었다. 순위 API의 천 달러 배율을 적용하지 않는다. [키움 공식 usa06012](https://openapi.kiwoom.com/m/guide/apiguide/36/usa06012)
- 수정종가×거래량으로 거래대금을 대체하지 않는다. 실제 거래대금이 빠지거나 비정상이면 해당 유동성 판정을 보류한다.

## 오류와 종목 유형

- 날짜 형식, 거래일 달력, 미래/미완성 날짜, 중복 날짜, 가격·거래량·통화, 고가/저가 범위를 검사한다.
- 오류 봉과 누락 거래일을 건너뛰어 30봉을 이어 붙이지 않는다. 이후 정상 이력이 다시 충분히 쌓여야 한다.
- 거래량 0은 데이터 오류와 구분한다. 큰 등락·넓은 가격 범위는 표식만 남긴다. 수익률이 크다는 이유만으로 정답을 제거하지 않는다.
- 국내는 카탈로그의 코스피·코스닥 일반 기업 후보를 사용한다. ETF·ETN·워런트·우선주·스팩 등 명확한 제품은 제외한다.
- 미국은 비ETF 기업형 후보를 사용하고 ADR·REIT 후보는 유지한다. 이름 기반 제품 제외는 추정임을 사유에 표시한다. 종목 종류를 완전히 검증한 보통주 목록은 아니다.
- 대소문자만 다른 종목코드를 자동으로 합치거나 바꾸지 않는다. 신원이 불확실한 키는 `review`로 격리한다.
- `exchange_calendars`의 역사적 XKRX/XNYS 거래일을 사용한다. 과거 한국 토요일 거래일을 주말이라는 이유로 없애지 않는다.

## 저장 구조

| 테이블 | 내용 |
|---|---|
| `daily_bars` | 승인된 30봉+다음날 표본에 필요한 원본 봉의 합집합. 구간 번호와 원본 행 ID 포함 |
| `training_samples` | 실제 사용 가능한 입력 시작일·종료일·정답 날짜·정답·구간 번호 |
| `instruments` | 실제 표본이 남은 종목 |
| `source_instruments` | 원본 전체 종목 목록 |
| `instrument_audit` | 모든 원본 종목 키의 포함/제외/검토 사유와 건수 |
| `bar_audit` | 검사한 후보의 제외 봉 또는 표식 있는 봉과 사유 |
| `sessions` | 정제에 사용한 거래일 달력 |
| `metadata` | JSON 값으로 된 정책, 버전, 원본 SHA-256, 완료 상태, 집계 |

종목 단계에서 제외한 자료는 `instrument_audit`에 합산 기록하며 해당 종목의 모든 봉을 중복 저장하지 않는다. 원본 DB에서 복원/재검토할 수 있다. `hard_error_occurrences`와 `flag_occurrences`는 한 봉에 여러 사유가 있어 합계가 행 수와 다를 수 있다.

**`daily_bars`에서 31행씩 임의로 잘라 쓰면 안 된다.** `training_samples`의 승인된 시작점만 사용한다. 기존 `examples.train_lstm30.load_dataset`은 정제 DB를 감지하면 이 색인을 검증하고 사용하며, 원본 DB의 이전 동작은 유지한다. 정제 DB의 메타데이터/색인이 누락되거나 작성 중이면 학습용 읽기를 거절한다.

이전 60봉 예제 `train_lstm_daily.py`는 이 30봉 정제 DB를 지원하지 않으므로 읽기를 거절한다. 다른 도구도 `training_samples`를 지원하도록 연결한 뒤 사용해야 한다.

## 실행

데이터 작업 폴더에서 실행한다. 출력 폴더는 새 경로를 지정해야 하며 기존 DB를 덮어쓰지 않는다.

```powershell
& 'C:/Users/user/Desktop/dockdack/.venv/Scripts/python.exe' -m dockdack.clean_daily_dataset `
  --source-dir 'C:/Users/user/Desktop/dockdack/data/kiwoom_daily' `
  --output-dir 'data/kiwoom_daily/clean-20260916-v1' `
  --market all --as-of 2026-09-16
```

`--as-of` 당일과 이후 날짜는 미완성 가능성이 있어 제외한다. 원본은 SQLite 읽기 전용으로 열고 생성 전후 파일/WAL의 SHA-256을 비교한다. 임시 `.building` DB에서 작성·외래키·무결성·행 수 검증을 마친 뒤에만 최종 이름으로 바꾼다. 실패한 `.building`은 자동 삭제하지 않고, 재실행은 새 출력 경로를 사용한다.

결과는 `domestic_daily_clean.sqlite3`, `us_daily_clean.sqlite3`와 각 `.summary.json`이다. `data/kiwoom_daily`는 Git에서 제외한다. 정제 DB를 읽을 때는 `?mode=ro` 연결을 권장한다.

## 남아 있는 한계

현재 수집 카탈로그 기반이어서 과거 상장폐지 종목 누락과 생존편향은 해결되지 않는다. 종목명·제품 분류도 과거 시점 기준 정보가 아니다. 수정주가의 모든 기업행사·혼합 수집 시점 일관성을 별도 검증한 것은 아니다. 과거 자유유통주식수, 호가 스프레드, 실제 체결 가능성도 없다. 이 정제는 품질·유동성 기준이며 수익성이나 실거래 적합성 보장이 아니다.

학습에서는 날짜순 학습/검증/평가 분리, 학습 구간에서만 정규화 계수 추정, 비용과 슬리피지를 포함한 별도 검증이 여전히 필요하다. 기존 모델 가중치는 이번 작업에서 재학습하지 않는다.

## 2026-09-16 실제 생성 결과

| 시장 | 표본이 남은 종목 | 저장 일봉 | 승인된 30봉 학습 표본 | 저장 날짜 범위 |
|---|---:|---:|---:|---|
| 국내 | 2,477 | 4,469,008 | 3,544,790 | 1999-03-15 ~ 2026-08-21 |
| 미국 | 4,974 | 12,145,737 | 11,508,494 | 1970-02-13 ~ 2026-09-11 |

종목 수는 역사 중 적격 구간이 한 번이라도 남은 종목이며, 현재 전부 유동성이 충분하다는 뜻이 아니다. 학습 표본은 30개 입력봉과 다음날 정답으로 이루어지며 서로 겹치므로 독립 관측 수가 아니다. 날짜는 종목별로 다르다. 원본을 새로 수집하거나 최신 날짜로 갱신하지 않았다.

원본 총 40,872,588행을 종목 분류/후보 품질 검사로 구분했으며, 원본 파일은 그대로다. 제외된 자료를 삭제했다는 뜻이 아니다. 검사 후보의 hard-invalid는 국내 2,096행, 미국 3,092행이다. 그중 국내 과거 달력 불일치 1,971행은 1989-10-12, 1992-12-28, 1993-07-07, 1994-01-03, 1994-02-14, 1994-05-20에 몰려 있다. 이 날짜들은 원본 오류인지 과거 달력 오류인지 확정하지 않았으며 검토 대상으로 남긴다. 최종 국내 보존 기간 이전이다.

두 DB 모두 원본 전후 SHA-256, SQLite 무결성·외래키, 원본 행 분류 합계 검증을 통과했다. 시장별 128개 표본의 원본 60거래일 유동성·30+1 입력/정답을 별도 계산으로 대조했고, 저장 OHLC 범위·거래량 형식 위반은 전수 검사에서 0개였다. 실제 학습용 읽기도 시장별 32종목으로 확인했으며 실제 DB로 모델을 재학습하지 않았다.

승인된 총 15,053,284개 표본의 달력 간격·시작/끝/정답 참조·구간 번호·정답 거래량을 독립 전수 검사해 위반 0개를 확인했다. 국내 23,729개·미국 16,046개 연속 구간 내부의 예정 거래일 누락도 0개다. 시장별 128개 저장 행의 원본 필드를 그대로 대조해 불일치 0개를 확인했다.

파일 크기·체크섬·집계·검증 기록은 [정제 결과 명세](datasets/clean-2026-09-16.json), 자세한 제외 이유는 각 DB의 감사 테이블과 같은 폴더의 `.summary.json`에서 확인한다. 최초 정제는 사용자 요청에 따라 미커밋 상태로 완료한 뒤, 후속 승인으로 정제 코드·정책·결과 명세를 Git 반영 대상으로 정리했다.

정제 DB 두 개는 합계 6,937,001,984바이트이며 데이터 작업 폴더 `C:/Users/user/Desktop/dockdack-data-collection/data/kiwoom_daily/clean-20260916-v1/`에 그대로 보관한다. **Git 병합은 DB 파일 자체를 업로드하거나 다른 작업 폴더로 복사하지 않는다.** 이번 반영에 별도 데이터 Release 업로드는 포함하지 않는다. 다른 환경에서는 원본 DB를 준비해 같은 기준으로 재생성하거나 이 정제 파일을 별도로 옮겨야 한다.
