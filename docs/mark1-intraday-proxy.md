# Mark1.13–1.22 장중 조회용 일봉 대리모델

이 문서는 새 모델 10개의 **학습 입력, 추론 연결, 검증 범위**를 기록한다. 이들은 과거 분봉·틱을 학습한 장중 경로 모델이 아니다. 완료된 일봉과 조회 시점 현재가로 점수를 계산하는 **모의투자 전용 prototype**이며, 장중 진입 뒤 목표가·손절가에 닿는 순서나 수익성을 검증하지 않았다. 모델 선택, 신호 생성, 주문 허용, 주문 접수, 체결은 서로 다르다.

## 데이터와 목표

- 학습은 저장소의 검증된 국내·미국 정제 일봉 캐시만 읽었다. 승인된 훈련 사건은 국내 200,000개, 미국 199,780개이고 목표일은 2010–2021년 훈련 분할이다. 두 시장의 캐시·원본 DB 체크섬과 표본 수는 각 번들의 `manifest.json`에 보존한다. 사건은 종목·날짜별 30봉 창으로 서로 겹칠 수 있으므로 독립 관측 399,780개라는 뜻은 아니다.
- 학습 입력은 목표일 **전까지 완료된 일봉**과 그 목표일에 관측된 **시가**다. 정답은 그 날 전체의 고가가 시가 대비 +1%에 닿고 저가가 −0.9%에 닿지 않은 경우다. 둘 다 닿은 날은 성공으로 세지 않는다. 고가·저가의 발생 순서는 일봉으로 알 수 없다. 목표일 고가·저가·종가는 특징으로 입력하지 않는다.
- 실제 추론에서는 목표일 시가 대신 **조회된 현재가**를 넣는다. 이미 진행된 장중 구간은 학습 정답의 `시가 → 당일 전체 고저가`와 다른 문제다. 출력 0–1은 이 대리사건에 대한 모델 점수이며 검증된 장중 성공확률, 예상 수익률 또는 매수 추천이 아니다. `0.5 초과`는 모의 신호 후보를 만드는 코드 기준일 뿐이다.
- 전체 프로세스에는 완료 일봉 30개가 전달되지만, 각 모델이 만드는 특징은 아래 표의 최근 구간을 주로 사용한다. 원본 첫 묶음의 일부 중심화 특징은 30개 전체를 사용한다. 따라서 30일을 무조건 모두 학습 특징으로 사용하거나 30일 초과 이력이 필요하다는 뜻이 아니다.

| 모델 | 구분한 특징 가설 | 실제 특징 최대 참조 구간 | 신경망 |
| --- | --- | ---: | --- |
| Mark1.13 | 1/5/10/20일 추세 지속·거래량 기울기 | 21봉 | 2층 GELU MLP |
| Mark1.14 | 단기 과매도·반전·30일 낙폭 | 30봉 | 2층 GELU MLP |
| Mark1.15 | 최근 고점/저점 돌파와 거래량 | 30봉 | 2층 GELU MLP |
| Mark1.16 | 변동성 국면·갭 변동 | 21봉 | 2층 GELU MLP |
| Mark1.17 | 거래량과 종가 위치의 압력 | 30봉 | 2층 GELU MLP |
| Mark1.18 | 1–3일 단기 반전과 5일 거래량 | 6봉 | SiLU MLP |
| Mark1.19 | 갭·몸통·위아래 꼬리와 캔들 위치 | 5봉 | Tanh MLP |
| Mark1.20 | 추세 가속과 단기 거래량 기울기 | 21봉 | GELU MLP |
| Mark1.21 | 변동성×거래량과 종가 압력 | 11봉 | 게이트형 MLP |
| Mark1.22 | 가격 범위 압축·확장과 20일 채널 | 21봉 | 3층 ReLU MLP |

두 시장별로 각 모델을 별도 특징·구조/초기화·가중치로 8 epoch씩 독립 학습했다. 전체 10개 모델 × 국내·미국 = **20개 체크포인트**다. Mark1.13–1.17은 `models/mark1_intraday/`, Mark1.18–1.22는 `models/mark1_intraday_extra/`에 따로 봉인한다. 기존 첫 묶음을 덮어쓰지 않기 위해 추가 묶음을 별도로 만들었다. 두 묶음의 `manifest.sha256`, 멤버별 SHA-256, 특징 코드 SHA-256과 모델 ID·시장·특징 순서를 로더가 대조한다. 파일이 없거나 값이 맞지 않으면 추론을 거부한다.

## 앱 연결과 주문 경계

10개 모델은 `AI 추론 모델 → 모델 선택`에서 개별 선택·해제하고 각 카드의 `1회 매수`에서 시장별 평가자산 대비 주문 예산 상한을 정한다. **저장된 선택이 없는 새 모의 계정에서는 전체 모델과 함께 초기 선택**되며 기존 계정의 저장 선택은 복원한다. 감시·자동주문은 앱 시작 시 항상 OFF다. 직접 체크해도 자동주문이 켜지거나 주문이 전송되지 않는다. 선택되면 모델별 독립 모의 신호 출처·별도 추론 프로세스가 사용되며, 추론 프로세스 자체에는 브로커 키·주문 권한이 없다. 실전 환경에서는 이 제공 prototype을 연결하지 않는다.

각 모델의 확인된 매수분에만 실제 체결 평균가 대비 +1% 익절·−0.9% 손절 후보가 적용된다. 모든 주문 후보는 앱에서 현재가·실제 지정가 재추론, 정규장·잔고·미체결·모델 lot·주문 수량/금액·가용액 등의 기존 안전 검사를 다시 통과해야 한다. 신호 하나나 점수 `0.5 초과`가 주문 또는 체결을 보장하지 않는다. 기존 Mark1.0–1.2의 서로 다른 장벽 추정확률 평균과 이 10개 **일봉 대리점수**는 합산하지 않는다.

## 재현·검증의 경계

오프라인 학습 코드는 `examples/train_mark1_intraday.py`와 `examples/train_mark1_intraday_extra.py`다. 둘 다 원본/정제 캐시를 읽기 전용으로 확인하고 새 출력 경로가 이미 있으면 덮어쓰지 않는다. 재학습은 별도 `--output` 경로에서 수행해 결과와 체크섬을 검토한 뒤 명시적으로 앱 번들을 갱신해야 한다. 학습 명령은 브로커 조회·주문·운영 장부 변경·GUI 자동주문 ON을 수행하지 않는다.

검증은 체크포인트 무결성, 두 시장의 로드 및 유한 점수, 모델별 ID/출처, 독립 작업자 RPC, 손상 파일 거부, GUI 선택·비중 보존과 가짜 서비스/임시 DB 경로를 대상으로 한다. **수익성 백테스트, 장중 분봉 경로, 실제 모의/실전 주문·체결은 이번 학습의 검증 범위가 아니다.** 향후 진짜 장중 목표가 선후 학습을 하려면 시각이 보존된 과거 분봉/틱, 체결·비용 가정, 진입시각별 라벨과 별도의 검증 설계가 필요하다.
