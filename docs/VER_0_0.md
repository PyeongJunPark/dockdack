# DOCKDACK ver 0.0 · 통합 자동매매 데스크

2026-09-16 작업 기준. `feat/broker-api`에서 개발하며, 사용자의 후속 요청으로
검증 후 커밋·푸시·main 병합한다. 이 배포 작업에서 신규 주문이나 운영 앱 재시작은 하지 않는다.
아래는 기능 계약이다. 실제 계좌에서 새 버전의 주문·체결까지 검증했다는 뜻은 아니다.

## 실행과 거래 환경

- `DockDack.vbs` 하나로 내장 LSTM과 외부 신호가 연결된 통합 데스크를 연다.
  직접 실행은 `python -m dockdack.v00_app`, 내장 모델 없이 실행은 `--no-model`을 사용한다.
- 2026-09-16 사용자가 스마트 앱 컨트롤을 끈 뒤 **내장 LSTM 실제 가중치의 CPU 추론을 확인했다**.
  PyTorch `2.14.0+cpu`에서 국내·미국 모델 모두 정상 로드되고 테스트용 30개 일봉으로 신호 JSON까지 생성했다.
  증권사 네트워크 호출·주문은 없이 가짜 계좌 응답을 사용했으며 모델 가중치는 변경하지 않았다.
  추후 모델 로드가 차단되면 앱에 원인을 표시하고 해당 LSTM 출처만 HOLD 처리하며 다른 외부 신호는 계속 처리한다.
- 시작 상태는 모의투자·자동주문 OFF다. 키가 있거나 앱을 켰다는 이유만으로 주문하지 않는다.
- 상단에서 모의/실전을 구별한다. 실전은 위험 경고 확인, 별도 실전 키,
  `DOCKDACK_ALLOW_LIVE_ORDERS=true`, 자동주문 확인이 모두 필요하다.
- 모드를 바꿀 때 감시와 주문을 중지하고 진행 중인 작업이 끝난 후 전환한다.
  장부·차트·신호·매매일지를 분리하며 모의 권한을 실전으로 승계하지 않는다.
- 이전 전용 LSTM30 모듈은 호환·테스트용으로 남아 있으나 별도 실행 바로가기는 제거했다.
  실전 설정의 상세는 [환경 선택 문서](trading-modes.md)를 참고한다.

## 관심종목 선정과 장 시간

- [x] 국내·미국을 각 거래소 현지 시간으로 독립 처리한다.
- [x] 개장 10분 전 초기 선정, 정규장 중 매 정시 거래량 TOP100 재선정.
- [x] 이 준비 구간과 정규장이 아니면 자동 순위 조회를 하지 않는다. 수동 TOP100 버튼도 같은 시간 제한을 따른다.
- [x] 수동 TOP100도 기존 자동관리 순위를 교체한다. 누를 때마다 이전 순위를 누적하지 않으며,
  조회 도중 폐장하면 결과를 적용하지 않는다.
- [x] 휴일·주말·미국 서머타임·조기 폐장·확인된 특별 개장시간을 반영한다.
- [x] 긴 전체 조회 때문에 정시를 지나거나 중간에 앱을 켰으면, 그날 가장 최근 선정 시각 한 번만 따라잡는다.
  지나간 모든 시간을 한꺼번에 호출하지 않는다.
- [x] 처리 완료한 시장/시각을 DB에 저장해 재시작 시 중복 선정하지 않는다.
  실패는 60초 이상 간격으로 같은 시각당 최대 3회, 중단된 작업은 10분 임대 만료 후 다시 맡는다.
- [x] 일반 기업 보통주만 선정하며, 분류 불명/짧은 응답으로 100종목을 확정할 수 없으면 기존 목록을 유지한다.
- [x] 순위에서 빠진 보유종목은 매수 관심목록에서 분리한다. 보유·주문 이력은 삭제하지 않는다.
  수동 고정 종목과 아직 해결되지 않은 주문은 별도로 남을 수 있어 화면 총수가 반드시 100개인 것은 아니다.

| 시장 | 초기 선정 | 장중 선정 | 거래량 API |
| --- | --- | --- | --- |
| 국내 KRX 일반 거래일 | 08:50 KST | 09:00~15:00 매 정시 | `ka10030`, `sort_tp=1`, `trde_qty` |
| 미국 일반 거래일 | 09:20 뉴욕 현지 | 10:00~15:00 매 정시 | `usa20530`, `qry_tp=0`, `acc_trde_qty` |

거래대금을 거래량으로 이름만 바꾼 것이 아니다. 두 거래량 필드는 모두 **주식 수**이며,
거래대금은 별도 필드다. 기존 `top_turnover` 함수는 호환용으로 유지한다.
차트 내보내기는 `ranking_basis`, `volume_rank`, `ranked_volume`, `ranking_fetched_at`으로 기준을 구별한다.

개장 전에는 브로커가 제공하는 **최신 일간 거래량 스냅샷**을 사용한다. 당일 정규장 거래량이
이미 발생했다고 가정하지 않으며 전일 자료일 수 있다. 초기 선정은 주문 허용이 아니고,
순위 호출이 실패해도 임의의 종목이나 거래량을 만들어 채우지 않는다.

공식 근거: [국내 거래량 API](https://openapi.kiwoom.com/guide/apiGuideContents/05/ka10030),
[미국 거래량 API](https://openapi.kiwoom.com/guide/apiGuideContents/35/usa20530).

## 매수 신호와 보유종목 매도 감시

- [x] 열린 시장의 매수 관심종목을 순회한 다음, 관심목록과 독립된 계좌 보유종목의 매도 조건을 순회한다.
- [x] 순위 이탈/관심목록 제외 때문에 보유종목 매도 감시가 사라지지 않도록 별도 계좌 스캔을 사용한다.
- [x] 매수 신호는 `take_profit_price`와 `stop_loss_price` 두 가격을 함께 전달할 수 있다.
  둘 중 하나만 전달하거나 상·하방이 뒤바뀐 가격은 거절한다.
- [x] 주문 직전 현재가가 하방 가격보다 높고 상방 가격보다 낮은지 다시 확인하며,
  접수가 확인된 매수에 연결된 목표를 장부에 저장한다.
- [x] 저장된 목표가 없는 기존 보유분은 사용자 확인대로 평균매입가 **+1% / -0.8%**를 사용한다.
  평균매입가를 확인하지 못하면 임의 목표를 만들지 않는다.
- [x] 보유종목 옆에 상방·하방 목표와 기준을 표시한다. 상방 이상/하방 이하일 때 매도 조건을 충족한다.
  이는 예상 주문 조건이지 해당 가격 체결이나 손실 한도 보장이 아니다.
- [x] 통합 데스크에서는 외부 매도 신호가 와도 저장된 목표 또는 기본 목표의 실제 돌파를
  새 현재가로 확인한다. 외부 매도 신호만으로 목표 검사를 건너뛰지 않는다.

외부 신호의 매수 항목에 추가할 가격 예시:

```json
{
  "take_profit_price": "101.00",
  "stop_loss_price": "99.20"
}
```

위 조각만으로 주문할 수 없다. 출처·종목·방향·수량·상한·생성/만료 시각·실제 내보내기 ID가 포함된
[전체 외부 신호 계약](external-signals.md)을 지켜야 한다. 숫자 가격은 문자열이다.

## 여러 신호기와 1회 매수 비중

- [x] 기본 신호 연결 외에 추가 `source_id`/JSON 입력 경로를 여러 개 등록한다.
- [x] 같은 출처/파일 중복, 차트 출력이나 DB를 입력으로 지정하는 설정은 거절한다.
- [x] 출처별 중복 신호 ID·유효기간·정책을 검사한다. 여러 신호기가 같은 종목을 가리켜도
  미체결/미확정 주문 및 기존 보유 확인을 건너뛰지 않는다.
- [x] GUI 기본 매수 비중은 시장별 평가자산의 **10%**이며 사용자가 변경할 수 있다.
- [x] 평가자산은 같은 시장·통화의 **예수금 + 보유 평가금액**이다. 주문당 상한을 예수금으로 간주하지 않는다.

매수 예산은 `평가자산 × 비중`, `주문당 상한`, `주문가능금액 ÷ 1.01` 중 최소값이다.
주문 직전 단가로 나누고 정수 주식 수로 내림하며 별도의 수량 상한도 적용한다.
1주를 살 수 없거나 예수금·평가액·주문가능금액이 불명확하면 그 매수를 보류한다.
주문당 상한과 10% 비중은 하루 누적 매수금액 한도가 아니다.

## 미국 지정가·재시도·체결 표시

- [x] 미국 자동주문은 현재가 지정가를 사용한다. 가격 자리수와 방향별 호가 처리는 수량과 별개다.
- [x] 증권사가 **거절했다고 확정한** 주문만 같은 주문 시도 묶음에서 최대 3회 시도한다.
  각 시도는 신호 만료·상하 목표·현재가·잔고·금액·수량을 다시 확인하고 별도 기록을 남긴다.
- [x] 로컬 OFF·시세 만료·장 종료·안전 검사 등으로 생긴 `OrderNotSent`는 즉시 재시도하지 않는다.
  새 주문 묶음은 해당 종목의 확정 거절 후 5분 재주문 대기시간을 지킨다.
- [x] 이미 접수됨/부분 체결/결과 불명/취소 대기 상태를 단순 실패로 간주해 중복 주문하지 않는다.
  지정가가 체결되지 않았다는 이유만으로 새 주문을 겹쳐 넣지 않는다.
- [x] 미국 주문별 조회에서 원주문·체결 수량과 체결금액을 대조해 평균 체결가를 보완한다.
  주문 지정가를 체결가로 표시하지 않으며 원주문 연결이나 수량이 모호하면 미확인 상태로 남긴다.
- [x] 주문 시도·거절·접수·미체결 확인 대기·체결을 주문 로그에서 구분하고 비차단 알림으로 안내한다.
  팝업은 새 승인창이 아니며 접수 알림이 체결을 뜻하지 않는다.

## 연속 운용과 화면

- [x] 한국·미국 각각 장중/장전/장 마감/휴장/확인 필요 상태를 상시 표시한다.
  설명에 현지 정규장과 한국 시간 기준을 함께 제공하며, API 호출 없이 캘린더로 갱신한다.
- [x] 초록색 진행 바는 관심종목 조회, 보유 목록 조회, 개별 보유종목 매도 조건 점검을 구분한다.
  응답 대기는 움직이는 표시와 경과 시간으로, 점검 완료 수는 실제 처리한 수로 표시한다.
  호출 제한 대기·응답 지연·장외 대기는 성공이나 체결로 표시하지 않는다.
- [x] 일반적인 종목 조회/신호 오류 때문에 전체 자동주문을 반복해서 OFF시키는 대신,
  오류가 난 종목·출처를 차단하고 다른 항목을 계속 처리한다.
- [x] 미국 잔고의 한글/영문 거래소 이름을 `ND/NY/NA`로 정규화한다.
  거래소를 해석할 수 없는 보유종목은 숨기지 않고 목표가 칸에 `확인 필요 · 보류`와 사유를 표시하며,
  그 종목만 자동매도에서 제외한다. 다른 시장의 감시·ON 검증은 중단하지 않는다.
- [x] 순회 보조 조회의 일시적 통신 오류·호출 제한은 이미 승인된 ON 상태를 유지하고
  정상 조회 주기에 다시 시도한다. 사용자 OFF를 자동으로 되돌리거나 실패 주문을 즉시 재전송하지 않는다.
- [x] 사용자 OFF/중지, 실전 권한, 환경 불일치, 금액/수량 검증, 미확정 주문 중복 차단,
  장부 기록 실패 등의 필수 주문 차단은 유지한다. '안전중단 비활성'은 검증을 모두 없앴다는 뜻이 아니다.
- [x] 상단 설명을 정리하고 중요한 현재 상태·주문 모드·동작 단계 위주로 표시한다.
- [x] 기록 조회와 선정 가능 시각 확인을 GUI 스레드 밖에서 처리하고,
  변경되지 않은 표/기록 재구성과 종목마다 반복되는 전체 장부 조회를 줄인다.
- [x] 모델 초기화는 작업 스레드에서 수행하고, 모델 진단 메모리와 알림 대기열을 제한한다.

## 예수금과 비중 매수

- 현재 예수금, 주문가능금액, D+1/D+2 추정예수금, 현금미수금은 서로 다른 값이다.
  API의 음수 현재 예수금을 0이나 절댓값으로 바꾸지 않으며 결제/미수 확인 안내를 함께 표시한다.
- 국내 현재 예수금이 음수일 때는 출처가 확인된 `kt00001.d2_entra`가 0 이상인 경우에만
  D+2 추정예수금 + 보유 평가금액을 비중 기준으로 사용한다(가상 매도 수수료·세금 차감 전).
  실제 매수 예산은 D+2 추정예수금과 주문가능금액 각각에 수수료 여유를 적용한 값,
  설정 비중, 주문당 상한 중 가장 작은 값으로 제한한다. D+2가 0이면 신규 매수를 하지 않는다.
- 결제 금액이 없거나 잘못된 경우에는 비중 매수를 보류한다. 국내 원화 추정치로 미국 달러 잔고를 대신하지 않는다.
  현재 예수금이 0 이상인 기존 계산 경로는 유지한다.
- 이는 계좌의 미수 자체를 없애거나 입금·결제를 수행하는 기능이 아니다.

공식 필드 설명: [키움 REST API 안내](https://openapi.kiwoom.com/guide/apiguide),
[예수금 상세현황](https://download.kiwoom.com/hero4_help_new/0362.htm),
[D+2 기반 추정자산 계산](https://download.kiwoom.com/hero4_help_new/4989.htm).

## 검증 범위
