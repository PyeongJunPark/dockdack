# Kiwoom REST API 요청 간격

## 공식 제한과 구현의 안전 여유

2026-09-15 [키움 REST API 소개](https://openapi.kiwoom.com/intro?dummyVal=0)의 호출 제한을 확인했다. 아래는 REST 기준이며 OpenAPI+ OCX의 제한과 혼용하지 않는다.

| 구분 | 공식 안내 |
| --- | --- |
| 모의 국내·미국 | 계좌/토큰별 동일 TR을 초당 1회 |
| 국내 실전 | 조회와 주문 각각 초당 5회 |
| 미국 실전 | 조회 초당 5회, 한국시간 09~10시에는 3회; 주문은 각각 10회/3회, 환전은 1회 |
| 미국 추가 제한 | 전체 초당 50회, 차트 초당 20회, `usa10099` 종목리스트는 분당 5회 |

키움의 숫자는 위 표이고, 다음 간격·쿨다운은 DockDack이 보수적으로 선택한 값이다. 서버가 이 간격을 요구한다고 주장하지 않는다.

- 모의 GUI는 API 응답 완료 후 최소 **1.25초**를 기다린다. 한 계좌의 모든 요청에 공통 간격을 적용하므로 서로 다른 TR을 빠르게 섞어 보내지 않는다.
- 미국 종목리스트 `usa10099`는 이전 응답 완료 후 **12.2초**도 기다린다. 연속조회 페이지와 같은 키를 사용하는 다른 클라이언트도 이 시각을 공유한다.
- 라이브용 라이브러리 기본 간격은 0.4초로, 미국 조회 피크 시간의 제한에도 여유를 둔다. GUI는 계속 모의투자 전용이다. 환전 기능은 구현하지 않는다.
- 전송 시각은 `이전 응답 완료 + 현재 간격`, `해당 TR의 추가 제한 시각`, `조회 쿨다운 종료` 중 가장 늦은 시각이다. 잠자기나 지연 뒤에도 실제 완료 시각에서 새로 계산하므로 밀린 요청을 몰아서 보내지 않는다.
- 같은 프로세스·호스트·App Key는 하나의 스케줄러를 공유한다. 키는 해시로 구분하고, 종료된 클라이언트의 스케줄러는 메모리에서 해제된다. 다른 프로그램/프로세스의 요청은 조정할 수 없으므로 같은 키로 여러 프로그램을 동시에 돌리지 않는 것이 좋다.
- `min_request_interval_seconds`를 코드에서 명시하면 테스트/별도 호출 제어용 간격을 사용한다. 이 경우 기본 안전 여유와 종목리스트 추가 간격을 대신하므로 운영 중 제한 회피를 보장하지 않는다. 현재 GUI는 이 덮어쓰기를 사용하지 않는다.

## 제한을 받은 경우

확인된 1700 거절은 응답을 처리하는 동안 공유 스케줄러에 반영한다. 조회 공통 쿨다운은 연속 거절에 따라 2.5 → 5 → 10 → 20초로 늘어나며 20초에서 제한한다. 조회 간격도 최대 5초까지 늘린다. 60초 동안 추가 1700이 없으면 기본 간격으로 돌아간다.

재시도는 정확한 `(API ID, 경로)` 허용 목록에 있는 조회만 최대 2회다. 알려진 1700 숫자 또는 키움의 정확한 1700 거절 메시지 이외의 타임아웃, 연결 오류, 잘못된 JSON, 일반 HTTP 오류를 재시도하지 않는다. 주문·정정·취소와 알 수 없는 API는 인증 갱신을 포함해 자동 재전송하지 않는다.

새 스케줄러에서 처음 연속 제한된 일반 조회의 재시도 대기는 2.5초와 5초다. 이미 제한이 반복된 상태라면 각 쿨다운이 최대 20초일 수 있다. 네트워크 응답 시간, 다른 요청 대기, 종목리스트 간격은 별도다. 이 정책은 제한 가능성을 낮추지만 외부 동시 호출이나 서버 정책 변경까지 포함해 제한이 절대로 발생하지 않는다고 보장하지 않는다.

## UI 상태와 주문 전 마지막 확인

`KiwoomHTTPClient.rate_status()`는 네트워크/DB 조회 없이 메모리만 읽는다. 실제 간격, 다음 전송까지 남은 초, 진행 중인 API, 제한·재시도 누적 횟수를 반환한다. UI는 `scope_id`가 같은 상태를 중복 합산하지 않아야 한다. 반환 시각은 Unix 시간이 아닌 monotonic 시각이다.

상태용 잠금은 네트워크/대기용 잠금과 분리되어 있어 조회가 진행되거나 쿨다운 중이어도 UI 상태 표시가 기다리지 않는다.

자동주문은 `order_send_guard(callback)` 범위에서 전송한다. 간격 대기가 **모두 끝난 뒤, 실제 HTTP 전송 직전** 콜백이 OFF·중지·시세 만료 등의 조건을 다시 검사한다. 거절 예외는 전송 불명으로 포장하지 않고 그대로 전달하며, 전송 횟수에도 포함하지 않는다. 이 범위는 중첩·스레드·실행 컨텍스트 사이에 누출되지 않는다.
