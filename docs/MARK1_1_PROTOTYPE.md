# mark1 / mark1.1 prototype — 외부 동시 신호 및 모델별 보유

2026-09-24, `mark_1` 작업 폴더의 일반 똑딱 GUI에 두 모델을 연결했다. 별도 관리 창을 만들지 않는다. 새 모델은 이미 학습한 +0.5% / −0.4% 모델에 독립된 이름과 출처를 부여한 저장본이며, 이번 연결에서 재학습하거나 확률을 바꾸지 않았다.

## 선택과 매도 기준

바탕화면의 `DockDack` 바로가기 또는 이 작업 폴더의 `DockDack.vbs`로 기존 통합 창을 열고, **매매 설정 → 외부 신호 연결 → 외부 AI 매수 신호기**의 두 체크박스를 사용한다. 기존 내장 드롭다운에는 prototype을 넣지 않는다.

| 선택 모델 | 저장 폴더 | 해당 모델 매수분 익절 / 손절 |
| --- | --- | --- |
| mark1 prototype | `models/mark1_prototype/` | 실제 평균매수가 +1% / −0.9% |
| mark1.1 prototype | `models/mark1_1_prototype/` | 실제 평균매수가 +0.5% / −0.4% |

- 두 모델을 독립적으로 켜고 끌 수 있으며 동시에 연결 가능하다. 기본 VBS는 두 연결을 선택하되 감시·주문은 OFF로 연다. 각 모델은 별도 외부 프로세스에서 추론·신호 생성하며, 별도 JSON 파일·상태 파일·출처 식별자를 사용한다. 한 모델이 실패해도 다른 모델의 파일을 덮어쓰지 않는다.
- 두 모델 모두 완료된 과거 30봉 + 후보 현재가를 사용한다. 보정 성공확률 **50% 초과**, 해당 모델의 보유분·미확정 매수가 없을 때 매수 후보이며 정확히 50%는 대기다. **다른 모델이 같은 종목을 보유/주문한 것은 그 자체로 매수 금지가 아니다.** 후보 현재가가 달라지면 재추론한다.
- 주문 전 새 현재가와 실제 지정가에서 다시 검증한다. 선택한 모델과 신호의 모델이 다르거나 검증기가 없으면 주문을 차단한다.
- 모델을 바꾸면 진행 중 조회를 정리하고 기존 주문 활성화를 해제한다. 새 모델 선택만으로 감시·자동주문을 시작하지 않는다. 사용자가 모의 환경과 수량·금액 한도를 확인한 뒤 기존 **자동주문 켜기 (ON)** 확인 과정을 거쳐야 한다.
- 매도 기준은 **원래 매수한 모델과 그 매수 건의 확인된 평균 체결가**에 따른다. 계좌의 합산 평균가를 각각의 매입가로 사용하지 않는다. 수량·금액·예수금 한도와 같은 신호 재전송 방지는 유지한다. 목표 도달은 주문 조건이며 실제 체결 보장은 아니다.
- 이 두 prototype은 **모의 전용**이다. 실전 차단, 연구용 표시, 연구 미통과 및 배포 불가 표시는 유지한다.

## 어떤 모델이 매수했는지 확인

**보유종목 / 실제 주문·체결 / 매매일지**에 `매수 모델` 열을 추가했다. 원본 신호 ID는 해당 셀의 툴팁에서 볼 수 있다. 새 매수 신호에는 전략 ID·모델명·모델 버전·번들 지문도 함께 저장한다.

| 출처 ID | 표시 모델 |
| --- | --- |
| `mark1-prototype-demo-trigger` | mark1 prototype |
| `mark1-1-prototype-demo-trigger` | mark1.1 prototype |

주문 내역은 장부의 원매수 신호에 연결하며 재시도 주문도 같은 원본을 따른다. 신호 출처·신호 ID·종목·시장·매수 동작을 대조한다. 재시작하거나 선택 모델을 바꿔도 현재 선택값으로 과거 주문을 추정하지 않는다. 출처 없는 수동·외부 거래는 `미확인 / 수동·외부`, 모순된 기록은 `출처 불일치 · 확인 필요`로 구분한다. 원매수 연결이 없는 과거 SELL에는 모델명을 지어 붙이지 않고 `매수 출처 미확인`으로 표시한다.

## 모델별 분리 보유와 청산

증권사 계좌는 같은 종목을 합산하므로 앱의 장부에서 **원매수 주문 ID별 가상 보유분(lot)**으로 구분한다. mark1 1주와 mark1.1 1주를 샀으면 보유현황에 같은 종목 2행으로 표시한다. 계좌 상단 총액은 증권사 합산값을 한 번만 표시한다.

- 주문 접수는 보유 수량이 아니다. 확인된 누적 체결 수량과 검증된 평균 체결가만 사용한다. 같은 체결을 반복 조회하거나 앱을 재시작해도 수량을 중복 적립하지 않는다.
- 매도 주문은 원매수 건에 연결하고 그 보유분 수량을 예약한다. 부분/지연 체결과 미체결 매도를 반영해 같은 물량을 다시 팔지 않는다. 실제 계좌의 매도가능수량도 전송 전에 확인한다.
- 원매수 주문이 부분 체결 중이면 나중 체결의 평균원가와 섞이지 않도록 해당 매수 건은 매수 주문의 체결 완료/취소 확인까지 청산을 보류한다. 다른 모델의 정상 매수분까지 같은 이유로 막지는 않는다.
- 모델별 합산 수량과 증권사 잔고가 다르거나 수동 매매·알 수 없는 과거 매도·원가 누락이 있으면 해당 종목의 모델 매매를 보류하고 원인을 표시한다. 모델/수량을 임의 배분하지 않는다. 기존 장부를 자동 수정하거나 실계좌를 재조정하지 않는다.
- 매도 일지의 원가는 지정한 원매수 건에 대응하며 다른 모델의 먼저 산 물량을 FIFO로 차감하지 않는다. 일반 거래는 기존 FIFO를 유지한다. 비용 전 로컬 기록 기준이며 세금/수수료 후 계좌 손익이 아니다.
- 매수 신호 연결을 꺼도 보유분의 모델·기준은 유지한다. 감시·자동주문이 사용자가 켠 상태라면 별도 보유 감시에서 매도 조건을 확인한다.

## 외부 프로그램 및 파일

GUI가 감시 중 각 모델 프로세스에 조회한 일봉·현재가·대조된 모델별 보유 정보만 전달한다. 자식 프로세스는 API 키/계좌 객체를 받지 않고 네트워크를 사용하지 않으며 주문할 수 없다. 매수 신호만 반환하고, 주문 전 현재가/호가단위 지정가의 새 추론도 같은 모델 프로세스로 검증한다. 프로세스가 죽으면 이전 JSON 파일만으로 주문하지 않는다.

이는 제공된 코드의 역할 분리와 네트워크 차단이다. 동일 사용자 권한으로 실행되는 Python 프로세스이므로 운영체제 보안 격리나 임의의 악성 코드를 안전하게 실행하는 샌드박스를 뜻하지 않는다.

장부 폴더 아래 `exchange/external-models/mark1-prototype/signals.json`과 `exchange/external-models/mark1-1-prototype/signals.json`이 각각의 입력 경로다. GUI에 경로를 표시한다. 사용자가 직접 관리하는 다른 외부 JSON 신호기도 기존 추가 연결 표로 계속 연결할 수 있다.

단독 데이터 신호 생성 예시(계좌 조회/주문 없음):

```powershell
python -m examples.run_prototype_signal --model mark1-prototype --chart charts.json --positions positions.json --output mark1-signals.json --state mark1-state.json --once
python -m examples.run_prototype_signal --model mark1-1-prototype --chart charts.json --positions positions.json --output mark11-signals.json --state mark11-state.json --once
```

모델별 파일은 서로 다르게 지정해야 한다. 단독 실행은 JSON을 만드는 것일 뿐 자동주문 활성화가 아니다. 과거의 `--trigger mark1-prototype` 실행 옵션도 외부 체크박스로 이전하지만 새 실행에서는 `--no-model --external-model mark1-prototype --external-model mark1-1-prototype`을 사용한다.

## 저장본과 연구 한계

mark1.1의 식별자는 `mark1-1-prototype`, 이름 버전은 `20260924-v1`, 원본 학습 버전은 `20260920-v1`이다. 원본 `models/mark1_0504/`의 모든 파일과 기존 `models/mark1_prototype/`은 그대로 보존한다. 새 이름의 묶음에는 원본 출처, 전체 파일 목록, SHA-256, 별도 이름 검증 기록을 추가했다. 파일 목록과 추론 래퍼까지 무결성 검사하므로 묶음 안에 임의 파일을 추가하거나 수정하면 로딩을 거부한다.

모델은 두 시장 모두 CatBoost 3-seed 앙상블과 확률 보정이다. 새 이름을 붙인 것이 새 신경망 학습이나 성능 향상을 의미하지 않는다. [원 재학습 결과](../reports/mark1-0504-20260920/REPORT.md)의 연구 미통과·비용 후 손실·국내 신호 표본 부족·미국 잔여 가격단위 문제 경고를 유지한다. 과거 미국 123신호는 재사용 역사 평가 결과이며 미래 장중 신호 수를 보장하지 않는다.

학습과 역사 평가는 실제 당일 시가 기준이다. 가격 입력을 바꿔 추론할 수 있어도 **임의 장중 진입 이후 남은 시간의 익절·손절 순서가 검증된 확률은 아니다**. 하루에 양쪽 경계를 모두 찍으면 손절 우선 실패 처리한다. 일봉만으로 장중 경로를 알 수 없다는 한계는 그대로다.
