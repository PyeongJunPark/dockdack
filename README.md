# DockDack

현재 앱 버전은 **ver 0.1 (MK1)**이다(패키지 버전 `0.1.0`). 통합 GUI, 기본 두 외부 모델과 선택형 Mark1.2 연결,
모델별 보유·체결 성과와 고급 설정의 현재 동작·제한은 [앱 기능 목록](docs/FEATURES.md)을 참고한다.
앱 버전과 모델 이름 `mark1 prototype`·`mark1.1 prototype`·`mark1.2 prototype`은 별개이며, [ver 0.0 안내](docs/VER_0_0.md)는 과거 개발 기록으로 보존한다.
두 모델의 실제 기술·데이터·학습 설정·평가 결과는 [MK1 / MK1.1 학습 명세](mark1.md)에 각각 정리했다.
후속 **Mark1.2**는 RTX 5080에서 가격 증강 +1%/−0.9% 신경망 7구조 비교 학습을 마친 별도 연구다. [학습·백테스트 결과](reports/mark1-2-20260924/REPORT.md)와 [후속 재검토](reports/mark1-2-20260925-review/REPORT.md)를 공개한다. 국내·미국 모두 연구 합격에 실패했으며 `research_qualified=false`, `deployment_allowed=false`는 그대로다. 사용자가 명시적으로 체크할 때만 기존 GUI의 **모의투자 전용 외부 신호기**로 연결된다. 실전은 차단하며 연결 자체는 수익성 승인이나 주문 ON이 아니다. GUI는 세 모델의 종목별 추정확률을 별도 열로 보여준다.
기본은 모의투자·자동주문 OFF이며, 실전은 별도 키·권한·경고 확인이 필요하다. 테스트 통과가 실제 체결 검증을 뜻하지는 않는다.

2026-09-24 감사 개선: [바뀐 점·검증 범위](docs/audits/2026-09-24/remediation.md), [전체 기능 목록](docs/FEATURES.md), [설치·테스트·장부 이관](docs/development.md). 일반 GUI에 모의계좌의 **정규장 마감 5분 전 국내·미국 매도가능 전량 청산**을 기본 선택으로 연결했다. 감시·자동주문 ON 승인이 필요하며 실전은 차단, 체결은 보장하지 않는다. 모델 가중치·추론 조건은 변경하지 않았다.

## 프로젝트 개요

딥러닝 모델을 이용해 금융시장의 매매 신호를 포착하고, 증권사 모의투자 API를 통해 자동으로 거래하는 인공지능 퀀트 투자 프로그램이다.

## 현재 사용 버전 — 기본 두 모델과 선택형 Mark1.2

`DockDack.vbs`는 일반 통합 GUI를 **감시·자동주문 OFF**로 연다. **신호 연결 → 모델·연결 설정 → 외부 AI 매수 신호기**에서 기본 선택된 `mark1 prototype`·`mark1.1 prototype`을 각각 켜거나, 기본 해제된 `mark1.2 prototype`을 명시적으로 추가할 수 있다. 세 모델은 동시에 연결할 수 있으나 선택만으로 주문하지 않는다. 내장 트리거 드롭다운에서 한 모델만 고르는 방식은 폐기했다. 모델별 별도 프로세스가 JSON 매수 신호를 만들고, 똑딱만 계좌 조회와 주문 권한을 가진다.

| 외부 모델 | 그 모델 매수분의 익절 / 손절 | 저장본 |
| --- | --- | --- |
| mark1 prototype | +1% / −0.9% | `models/mark1_prototype/` |
| mark1.1 prototype | +0.5% / −0.4% | `models/mark1_1_prototype/` |
| mark1.2 prototype (명시적 선택) | +1% / −0.9% | `models/mark1_2_prototype/` |

선택된 모델들은 **같은 종목을 각각 매수할 수 있다**. 확인된 체결 수량·체결가를 모델/매수 건별 가상 보유분으로 저장하고, 각 매수분의 기준으로 해당 수량만 매도한다. 증권사의 종목별 합산 잔고와 대조하며 불일치·체결원가 미확인 시 임의로 나누어 매도하지 않는다. 동일 모델의 신호 재전송·미확정 주문 중복과 매도가능수량 초과는 계속 차단한다. 보유현황·주문/체결·매매일지에서 `매수 모델`을 확인한다.

일반 화면은 외부 AI 연결 중심이다. 수동 가격·이동평균 규칙, 외부 모드 전환, 구형 LSTM·랜덤 테스트 신호기는 하단 **기타·고급 설정** 안에 보존하며 기본 화면에서는 숨긴다. 열고 닫아도 실행 방식이나 주문 권한은 바뀌지 않는다. 감시 중에는 설정 편집을 잠그며, 모든 AI 연결을 끈다고 수동 규칙을 자동 실행하지 않는다.

**모델 성과** 탭은 백테스트가 아닌 저장된 체결 원장을 바탕으로 모델별 **누적 실현 수익률**을 표시한다. 매도분 매수원가 대비 실현손익의 비율이며 수수료·세금과 미매도 평가손익은 제외한다. KRW/USD와 모의/실전 계정은 별도로 집계하고, 근거가 없으면 `기록 없음` 또는 `확인 필요`로 표시한다. 원장은 계정별 DB에 남아 재시작해도 재계산되며, 이 탭을 열어도 조회·주문 권한이 활성화되지는 않는다. 세 prototype의 모의 전용 제한은 유지되므로 모의 체결을 실전 수익으로 표시하지 않는다.

세 모델 모두 완료 30봉 + 현재가, 모델 추정 성공확률 >50%, **모의 전용**이다. 기존 MK1·MK1.1은 CatBoost 3-seed, 선택형 MK1.2는 국내 CNN·미국 LSTM 3-seed 앙상블이다. MK1.2의 2025+ 재사용 역사 백테스트는 왕복비용 20bp 가정에서 국내 −5.8640%, 미국 −6.9049%였다. 세 모델 모두 연구 기준을 통과하지 못했고 장중 체결 경로·비용 후 수익성 문제가 남았다. 모의 연결은 수익성 입증이나 실전 배포를 의미하지 않는다. 사용자가 기존 ON 확인 과정을 거쳐야 주문한다.

설치: `uv sync --extra gui --extra prototype`. 실행/외부 JSON 계약/모델별 보유 관리는 [GUI 사용 안내](docs/gui.md)와 [외부 신호 안내](docs/external-signals.md)를, 기존 두 모델의 상세는 [MK1·MK1.1 안내](docs/MARK1_1_PROTOTYPE.md)를 참고한다. 주요 브랜치는 `main`(통합본), `mark_1`(개발)이다.

로컬 작업은 저장소 폴더 하나에서 관리한다. 정제 DB는 `data/kiwoom_daily/clean-20260916-v1/`, 모델은 `models/`, 학습 결과와 선택 실행 패키지는 `outputs/mark1/`에 둔다. 키·장부·로컬 복구 자료는 GitHub에 게시하지 않는다. 기존 작업 폴더 통합과 과거 연구 경로의 제한은 [정리 기록](docs/cleanup-20260924.md)을 참고한다.

## 개발 목표

1. 시장 데이터를 수집하여 매매 신호를 생성하는 딥러닝 모델을 학습하고, 최신 시장 정보를 기반으로 추론할 수 있도록 한다.

2. 실시간 시장 정보 조회와 모의주문이 가능한 증권사 API를 연동하여 자동매매 시스템을 구축한다.

3. 다양한 논문과 기술에서 가설을 도출하고, 백테스트와 모의투자를 통해 검증하면서 딥러닝 모델을 지속적으로 개선한다.

## 마일스톤

### M1. 데이터 수집 시스템 구축

- 주식 종목 정보를 수집한다.
- 가격 및 거래량 데이터를 수집한다.
- 수집한 데이터를 저장하고 관리한다.
- 데이터 오류와 누락을 검사한다.

### M2. 키움증권 API 연동

- 키움증권 REST API를 연동한다.
- 실시간 시장 정보를 조회한다.
- 모의계좌의 잔고와 보유 종목을 조회한다.
- 모의주문과 주문 취소 기능을 구현한다.
- 주문 및 체결 결과를 기록한다.

### M3. 모델 학습 및 검증 시스템 구축

- 학습에 사용할 데이터셋을 생성한다.
- 기본 매매 전략을 구현한다.
- 딥러닝 모델을 학습한다.
- 백테스트를 통해 모델의 성능을 검증한다.
- 실험 조건과 결과를 기록한다.

### M4. 자동 모의거래 시스템 구축

- 최신 시장 데이터를 모델에 입력한다.
- 모델이 매매 신호를 생성하도록 한다.
- 매매 신호에 따라 모의주문을 실행한다.
- 중복 주문과 비정상적인 주문을 방지한다.
- 거래 결과와 시스템 오류를 기록한다.

## 향후 계획

- 새로운 가설을 정의하고 검증한다.
- 논문과 기술 자료를 참고하여 새로운 모델을 실험한다.
- 기존 모델과 새로운 모델의 성능을 비교한다.
- 검증된 모델을 모의투자 시스템에 적용한다.
- 모의거래 결과를 바탕으로 모델과 시스템을 개선한다.

키움증권 브로커 모듈의 설치, 키 설정, 사용 예제는 [키움증권 브로커 문서](docs/kiwoom-broker.md)를 참고한다.

국내·미국 전 종목의 최장 일봉 OHLCV 수집 방법과 수집된 DB 다운로드는 [키움 전 종목 일봉 데이터셋 문서](docs/daily-dataset.md)를 참고한다.

원본을 보존하면서 저유동성·오류 구간을 거르고 30봉 학습 표본을 만드는 방법은 [딥러닝용 일봉 정제](docs/dataset-cleaning.md)를 참고한다.

수집한 일봉으로 다음 거래일 상승 여부를 학습하는 [PyTorch LSTM 예제](docs/lstm-example.md):

```powershell
uv sync --extra ml --inexact --no-install-project
uv run --no-sync python examples/train_lstm_daily.py --epochs 20
```

학습된 모델과 현재가를 연결하는 [매매 신호 예제](docs/trading-signals.md)는 `UP` + 전일 대비 하락 시 매수, `NOT_UP` + 전일 대비 상승 시 보유분 매도, 평균 매입가 대비 +1% 이상이면 우선 매도 신호를 출력한다. 주문은 전송하지 않는다.

새 [30봉 LSTM 전략 모듈](docs/lstm30-strategy.md)은 국내·미국 DB의 여러 종목으로 다음 종가 +1% 이상 상승 여부를 학습한다. 미보유 시 예측에 따른 매수, 보유 시 실제 평균 매입가 대비 +1% 익절·−0.8% 손절 신호를 main의 외부 신호 규격으로 제공한다. 기존 60일 예제와 별도이며 모듈만 불러오면 주문하지 않는다. [학습 가중치](models/lstm30/README.md)와 [명시적 승인 기반 연속 모의 실행기](docs/lstm30-demo-runtime.md)를 제공한다. 실전 실행은 지원하지 않는다.

## 터미널에서 조회·주문

`mark_1`에서는 [완료 30봉 + 현재가 기반 장벽 모델](docs/mark1-strategy.md)을 별도로 실험한다. MLP·LSTM·GRU·TCN·Transformer와 가격 증강 대조군의 [실측 성능 비교](reports/mark1-20260916/REPORT.md)를 제공한다. 매수는 보정 확률 **50% 초과**, 매도는 평균 매입가 대비 **+1% / −0.9%**이며, [전용 GUI](docs/MARK1_GUI.md)는 감시·자동주문 OFF로 시작한다. 일봉의 하루 전체 사건 확률이며 장중 진입 이후의 익절/손절 순서는 검증되지 않았다.

후속 [mark_1 포트폴리오 백테스트](reports/mark1-backtest-20260916/REPORT.md)는 같은 날 양쪽 경계 도달 시 손절 우선으로 계산한다. 정제 승인 평가 기간 전체, 초기 자금·정수 수량·동시 보유·비용·갭을 반영하고, 보유형과 당일 청산형의 자산 곡선·낙폭·전체 거래 내역을 제공한다. 결측 보유 경로가 있는 결과는 잠정치이며 실제 체결 실적이 아니다.

심층 후속 연구는 [실패 원인 진단](docs/mark1-deep-audit.md), [논문 조사](docs/mark1-deep-research.md), [고정 실험 계획](docs/mark1-deep-protocol.md)을 바탕으로 1D ResNet-18/34·InceptionTime 계열·MLP를 비교한다. [실측 결과와 수익 곡선](reports/mark1-deep-20260916/REPORT.md)에서 두 개발 검증 구간과 3-seed 앙상블, 기존 모델과의 동일 표본 비교를 확인할 수 있다. 이미 본 2025년 이후 자료는 재사용 역사 평가이며 새 미사용 시험이 아니다. `dockdack.mark1_deep_inference.DeepPredictor`는 별도 연구용 추론 모듈로, 기존 GUI 모델을 교체하거나 주문을 허용하지 않는다.

후속 [정밀도 우선 연구 계획](docs/mark1-selective-protocol.md)은 신호가 드물어져도 실제 매수 성공 비율을 높이는 것이 목표다. [추가 AI·퀀트 문헌 검토](docs/mark1-selective-literature.md)를 바탕으로 과거 30봉의 184개 특징, CatBoost/LightGBM, 별도 기간에서 고른 보류 임계값을 비교한다. p>50%는 최소 조건이며 더 높은 문턱이 추가될 수 있다. 연구 통과와 실제 배포는 별개이고, 0건 신호를 성공으로 표시하지 않는다. 기존 GUI·주문 모델은 자동 교체하지 않는다.

[정밀도 우선 연구의 실제 결과와 그래프](reports/mark1-selective-20260916/REPORT.md): 24회 학습 후 국내 재사용 역사 신호 성공률은 이전 심층 모델 36.16%에서 49.89%로 개선됐지만, 신호는 307개에서 441개로 늘었고 비용 후 보유형 −2.30%·당일 청산형 −2.69%로 여전히 손실이다. 미국은 무신호이며 양 시장 모두 연구 기준 미통과다. 선택된 고정 정책은 기본 p>50%와 같아 **더 드문 고정밀 신호를 달성했다고 볼 수 없다**. 별도 `dockdack.mark1_selective_inference.SelectivePredictor`는 확률·연구용 선별 여부·+1%/−0.9% 가격을 반환하지만 항상 배포 불가로 표시하며 주문 기능은 없다. 사용법과 저장 위치는 [연구 계획의 실행/추론 절](docs/mark1-selective-protocol.md#실행-결과와-연구용-추론)에 있다.

선정 후보를 보존한 **[mark1 prototype](docs/MARK1_PROTOTYPE.md)**은 `models/mark1_prototype/`의 국내 `cat_joint6`·미국 `cat_binary8` 3-seed 모델이다. 확률 >50%일 때 매수 후보를 만들고, 해당 모델 매수분에는 +1% 익절·−0.9% 손절을 적용한다. 현재는 위의 외부 동시 연결 방식으로 사용하며 실전 차단·연구 미통과·미국 과거 무신호·데이터 경고를 유지한다.

별도 **[+0.5% / −0.4% 재학습](docs/MARK1_0504.md)**은 정제 DB의 정답과 과거 장벽 특징을 새 기준으로 다시 만든다. 기존 선정 CatBoost 구조의 국내·미국 3-seed 앙상블을 시간 분리 검증하고, [같은 표본에서 기존 모델과 비교](reports/mark1-0504-20260920/REPORT.md)한다. 새 가중치는 `models/mark1_0504/`에 보관하며, **그 재학습 작업 당시에는 기존 GUI·자동주문·보유분 매도 기준을 바꾸지 않았다**. 후속 연결은 아래 mark1.1 안내와 구분한다.

이 +0.5% / −0.4% 모델은 **[mark1.1 prototype](docs/MARK1_1_PROTOTYPE.md)** 이름으로 `models/mark1_1_prototype/`에도 보존했다. 기존 두 prototype은 기본 외부 AI 신호기이고, 별도 Mark1.2는 사용자가 명시적으로 선택하는 세 번째 모의 신호기다. 모든 모델의 매수분은 출처별로 분리한다. 아래와 과거 개발일지의 단일 내장 선택 방식은 개발 이력이며 현재 사용법이 아니다.

일반 GUI에서 **모의투자 / 실전투자**를 선택할 수 있다. 기본은 모의이며, 실전 선택에는 위험 경고와 별도 API 키·주문 허용 설정이 필요하다.
실전 경로는 가짜 응답으로만 검증했으며 **실제 계좌 주문·체결 검증은 하지 않았다**. [거래 환경 선택과 안전 장치](docs/trading-modes.md)를 참고한다.
기존 미국 모의 체결 관찰은 `DEVLOG.md`에 별도 기록되어 있다. ver 0.0의 새 체결가 보완·재시도 경로는
가짜 응답으로 검증하며, 이번 변경을 실제 모의/실전 주문 성공으로 표시하지 않는다.

창에서 사용하려면 프로젝트 폴더의 **`DockDack.vbs`를 더블클릭**한다.
최초 설치는 `uv sync --extra gui --extra prototype`으로 한다. [GUI 사용 설명](docs/gui.md)을 참고한다.

`.env.example`을 참고해 프로젝트 루트의 `.env`에 사용할 시장의 키를 설정한 뒤 실행한다.

```powershell
uv run dockdack
```

한국 종목코드(`005930`) 또는 미국 티커(`AAPL`)를 입력하고 메뉴에서 현재가,
지정가/시장가 매수·매도, 미체결, 잔고를 선택한다. 미국 거래소는 키움 API로 자동 조회한다.
기본 환경은 모의투자이며, 주문 전 내용을 표시하고 확인을 받는다.

한 번만 조회하려면 `uv run dockdack quote AAPL`처럼 실행한다.
자세한 설정과 주문 예시는 [터미널 사용법](docs/terminal.md)을 참고한다.

## 관심종목 · 자동매매

통합 GUI의 관심종목과 매매 설정에서 종목을 저장하고 최근 N거래일 차트와 현재가를 조회할 수 있다.
일반 수동 트리거 모드에서는 가격 이상/이하 또는 N일 이동평균 이상/이하 조건에 매수·매도, 수량, 주문금액 상한을 연결한다. 외부 신호 모드에서는 이러한 수동 규칙을 실행하지 않는다.
감시는 기본 꺼짐이며, 조회 감시와 자동주문 활성화는 별도다. 환경 전환 시 감시·자동주문을 중지하고 장부·잔고·규칙을 분리한다. 주문 규칙은 한 번만 시도하고 재시작 후에도 자동 재전송하지 않는다.
자세한 설정·중지·미확정 주문 처리 방법은 [자동매매 사용법](docs/autotrading.md)을 참고한다.

**한국·미국 각각 일반 기업 보통주 거래량 TOP100**을 선정하고, 차트를 JSON으로 내보내 외부 모델의 `buy`/`sell`/`hold` 신호를 연결할 수 있다.
ETF·ETN·펀드·우선주·리츠·스팩과 분류가 불명확한 종목은 제외한다. 자동주문 직전에도 보통주 분류를 재검증한다.
GUI의 **외부 신호 연결** 탭에서 입력 파일과 수량·시장별 금액 상한을 설정한다. 신호를 읽는 것만으로 주문이 켜지지는 않는다.
파일 규격과 모델 연결 예제는 [외부 신호 연동 문서](docs/external-signals.md)를 참고한다.

감시 중에는 시장별 **개장 10분 전 초기 선정 → 실제 개장 시각 → 장중 현지 매 정시**에 TOP100을 재선정한다. 미국 09:30 개장도 별도 갱신하며 휴장·조기폐장·미국 서머타임을 반영한다. 실시간 순위가 아니라 각 선정 시점의 보통주 거래량 순위이며, 수동·미확정 주문 보호 종목 때문에 화면 총수는 100개를 넘을 수 있다.
과거 일봉은 SQLite에 저장해 재시작 후에도 재사용하고, 당일 봉과 누락된 최근 거래일만 증분 갱신한다.
외부 신호 모드에서는 종목 조회가 끝나는 즉시 개별 차트 JSON을 갱신한다.
**모의 테스트 신호기** 탭에는 미보유 종목 **10% 매수 / 실제 평균 매입가 대비 +1% 익절 · -0.8% 손절** 테스트를 연결했다.
이 랜덤 테스트 신호 자체의 수량은 각 1주이며, 현재 통합 데스크의 비중 매수가 켜져 있으면 실제 매수량은 설정 예산에 맞게 다시 계산된다. 임계값은 신호 조건이며 그 가격의 체결이나 순수익을 보장하지 않는다.
현재 통합 데스크의 초기 매수 설정은 시장별 평가자산 10%, 주문당 국내 1,000만원·미국 10,000달러 상한이다. 이는 권장 투자금액이나 하루 누적 한도가 아니며 사용자가 설정을 확인해야 한다. 기본 감시·자동주문은 OFF이고, 금액 0으로 설정한 시장은 차단된다. prototype 주문은 현재가 지정가이며 랜덤 테스트기의 국내 시장가 선택과 구분한다.
운영 순서, 일정 예외, 파일 위치와 안전 제한은 [지속 감시 운영 안내](docs/server-mode.md)를 참고한다.

**실제 주문·체결**에서는 증권사 체결가를 다시 확인하고 매도별 대응 원가·실현손익·수익률을 볼 수 있다.
이전 기록은 주문번호·종목·방향·수량·조회일 등의 근거가 일치할 때만 보완하며 현재가/주문가를 대신 넣지 않는다.
미국 과거 기록은 API 조회일의 시간대 근거가 확인되지 않아 자동 가격 보완을 보류한다.
손익은 화면의 500건 제한 밖 기록까지 포함한 **이 앱의 전체 자동주문 장부**를 사용한다. 모델별로 배분한 매도는 지정된 원매수 건의 원가를 사용하고, 일반 매도는 주문순서 FIFO를 유지하며 수수료·세금을 제외한다.
매수 원가나 체결가가 없으면 `미확인`으로 표시한다. 수동·다른 앱 주문을 포함하는 계좌 전체 손익은 아니다.
조회 간격과 확인 범위는 [체결가 보완과 실현손익](docs/gui.md#체결가-보완과-실현손익)을 참고한다.
